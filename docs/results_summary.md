# 발표용 결과 정리

발표 슬라이드에 그대로 옮길 수 있게 결과를 한곳에 모았다. 숫자마다 근거 문서를 적었다.
11주차(11/06) 기준이다.

담당: 이예진 / 상태: 11주차 결과에 6.2 확정본 수치(11/16), 7.3 기기 측정과 12주차 판정 실험(11/19)을 반영

## 한 줄 요약

**가정한 카메라 자세 잡음을 넣은 시뮬레이션에서, 위치 오차를 반경으로 담아 판정하면 한 점
조회보다 틀린 용도 단정이 18.3% 에서 3.7% 로 준다. 경량 VLM 은 문장을 쓰지 않고 탐지 조각이
연기인지만 판정하고, 시뮬레이터 한 장면에서 헛탐지 자리로 가는 알람이 27건에서 13건으로 줄었다.**

두 수치 모두 실제 비행으로 잰 값이 아니다. 어디까지 말할 수 있는지는 각 절과 7절에 적었다.

## 1. 핵심 주장: 반경 판정이 틀린 단정을 줄인다

발화점 600곳, 드론 거리 200~800m, 카메라 자세 잡음 포함. 정답은 실제 발화점의 용도다.
(`docs/verdict_compare.md`)

| 방식 | 틀린 단정 | 확정했을 때 정확도 |
|---|---|---|
| C 한 점 조회 (기존 방식) | 18.3% | 81.7% |
| D 반경 판정, 자세 오차 항 없음 | 8.2% | 86.5% |
| **D+ 반경 판정, 자세 오차 항 포함** | **3.7%** | **92.4%** |

- 틀린 단정 80% 감소 (차이의 95% 신뢰구간 12.0~17.7%p)
- 판정을 실제로 쓰는 200~400m 만 보면 14.1% → 12.5% → **5.7%**
- 대가: 확정이 100% 에서 48% 로 줄고 나머지는 모호와 미확정이 된다. 모르는 것을
  모른다고 말하는 것이 목표다
- 줄어든 틀린 단정에는 확정 자체를 줄인 몫이 들어 있다. 한 점 조회도 같은 비율(48%)만
  확정하게 맞추면 정확도가 85.5~85.8% 로, 반경 판정(92.4%)이 여전히 높다. 다만 반경을 50m 로
  고정해도 92.7% 라, 계산한 반경이 고정 반경보다 낫다고는 말할 수 없다(`docs/verdict_coverage.md`)
- 넣은 잡음의 크기(수평 2m, 고도 2m, 기수 2도, 카메라 각도 1도)는 가정한 값이고, 반경
  공식에도 같은 값을 썼다. 잡음을 2배로 키우면 틀린 단정은 한 점 조회 22.2%, 반경 판정
  5.0% 다. 반경이 잡음을 다 담지 못해 포함률은 84% 에서 71% 로 준다(`docs/verdict_sensitivity.md`)
- 탐지 오차는 시뮬레이터 31장에서 잰 픽셀 차이를 600곳에 옮겨 쓴 것이다. 그래서 실제
  불확실성은 위 신뢰구간보다 클 수 있다

**슬라이드 메시지: 반경 판정은 반경이 실제 오차를 담을 때만 효과가 있다.**

## 2. 오차 반경이 실제 오차를 담도록 고쳤다

시뮬레이터 정답 픽셀에 카메라 자세 잡음(수평 2m, 고도 2m, 기수 2도, 카메라 각도 1도)을
300번 섞어 정답이 반경 안에 드는 비율을 쟀다. (`docs/simulator.md`, PR #26)

| 거리 | 고치기 전 포함률 | 고친 뒤 포함률 |
|---|---|---|
| 200m | 72% | 100% |
| 400m | 52% | 97% |
| 600m | 33% | 92% |
| 800m | 18% | 88% |

- 포함률은 반경 공식에 넣은 것과 같은 크기의 잡음으로 잰 값이다. "가정한 잡음을 담는다"는
  뜻이고, 실제 비행의 오차를 담는지는 재지 못했다
- 원인: 반경에 GNSS 오차만 있고 기수와 카메라 각도 오차가 빠져 있었다
- 고친 것: 반경에 자세 오차 항 `2·sqrt((d·σψ)² + (h·σθ/sin²dep)² + (σh/tan dep)²)` 추가

## 3. VLM 의 역할: 탐지 조각이 연기인지 판정한다

11/03 면담에서 VLM 이 위치 추정에 기여하게 하라는 요청이 있었다. 네 가지를 시험했다.
(`docs/vlm_base_pick.md`)

| 시도 | 결과 |
|---|---|
| ① 여러 후보 중 진짜 연기 밑동 고르기 | 신호 없음 |
| ② 밑동이 능선에 가려졌는지 판단 | 신호 없음 |
| **③ 탐지 조각마다 연기인지 판정 (후보 검증기)** | **실제 사진 AUC 0.92** (평가셋, 장소 두 곳). 장소를 섞은 150장에서는 0.74 |
| ④ 모호 판정에서 밑동 둘레가 숲인지 시가지인지 고르기 | 건물은 잘 봄(AUC 0.9). 그러나 완벽하게 읽어도 GIS 로 추정 위치 한 점을 조회한 것과 같음(모호 79개 중 62). 쓰지 않음 |

검증기를 파이프라인에 넣은 결과. 시뮬레이터 32장, 1.5초 간격, RTX 3050 4GB.
(`docs/vlm_compare.md`, PR #27)

| | 검증기 끔 | 검증기 켬 |
|---|---|---|
| 알람 | 47 | 28 |
| 정답에서 100m 넘게 떨어진 알람 | 27 | **13** |
| 탐지에서 알람까지 중앙값 | 2.0초 | 1.9초 |
| 알람 뒤 위치 수정까지 | | 12~16초 |

- 알람은 YOLO 로 먼저 내고, 검증기가 뒤에서 위치를 고친다. 알람이 늦어지지 않는다
- 실제 사진 65장에서도 헛탐지로 좌표를 낸 사진이 6장 → 2장 (고침 4, 망침 0). 바뀐 사진이
  4장뿐이라 통계적으로 유의하지는 않다(McNemar p=0.125)
- 위 표는 시뮬레이터 한 장면 32장을 한 번 돌린 값이다. 지형 자료가 시뮬레이터와 달라
  실행끼리의 상대 비교로만 본다
- 검증기 AUC 0.74 는 장소를 섞은 150장의 값이다(PR #35 `docs/vlm_situation.md`). 150장 중
  117장이 탐지 모델이 학습한 영상이라 0.92 와 그대로 비교할 수는 없다

**슬라이드 메시지: 경량 VLM 은 설명보다 판정에 강하다.**

## 4. 설명 문장: 규칙이 쓰면 과신이 0 이 된다

평가셋 100장, 입력 조건 D, 같은 VLM. (`docs/generation_methods.md`)

| 생성 방식 | 판정 준수 | 과신률 | 장당 시간 |
|---|---|---|---|
| (i) 프롬프트만 | 50% | 37% | 9.4초 |
| (ii) 규칙 검증 후 재생성 | 83% | 14% | 20.3초 |
| **(iii) 구조화 출력 + 템플릿** | **100%** | **0%** | **6.5초** |

- 대가는 정보량이다. 요소 포함 51% 로 가장 낮다
- (ii) 는 재생성 2.1회를 더 쓰고도 100% 에 닿지 못한다
- (iii) 의 판정 준수 100%, 과신 0% 는 문장을 규칙이 쓰기 때문에 설계상 나오는 값이다.
  채점도 같은 규칙으로 한다. 사람이 문장을 읽고 매긴 평가는 아직 없다

## 5. VLM 이 본 사실은 검증하고 쓴다

VLM 이 사진에서 본 것을 문장에 넣기 전에 따로 쟀다. 늘 같은 답보다 못한 것은 뺐다.
(`docs/vlm_compare.md`)

| 사실 | VLM | 비교 기준 | 결정 |
|---|---|---|---|
| 연기 유무 (100장) | 사진 전체 66/100 | YOLO 90/100 | YOLO 로 정한다 |
| 연기색, 사진 전체 (70장) | 24/70 | 늘 "흰색/회색" 40/70 | 뺀다 |
| 연기색, 탐지 조각 (60장) | 42/60 | 늘 "밝은색" 33/60 | 뺀다 (열에 셋 틀림) |
| 불꽃 (57장) | 0/19 잡음, 헛말 0/38 | 따로 물으면 AUC 0.85 | 지금은 쓰지 않는다 |

**슬라이드 메시지: 모델이 말할 수 있는 것만 말하게 한다.**

## 7. 한계 (발표에서 먼저 말할 것)

- **위치 수치는 시뮬레이터에서 낸 것이다.** 71330 사진에는 촬영 좌표와 카메라 방위가 없다.
  해외 공개 데이터(미국 HPWREN)도 찾아봤으나 거리가 수~수십 km 이고 정답 좌표 자체가
  0.5~1km 틀려, 카메라 여러 대를 쓴 선행 작업도 오차 중앙값이 1.9km 였다. 400m 안을
  다루는 이 과제의 검증에는 쓸 수 없다
- **600m 넘으면 사실상 모두 미확정이다.** 시연과 운영은 400m 안으로 한다
- **200m 에서도 틀린 단정 12% 가 남는다.** 탐지가 밑동을 잘못 짚는 오차이고, 반경 공식은
  이 오차를 담지 않는다
- **평가셋 수치는 6.2 확정본으로 다시 잰 값이다(11/16).** v1 보다 조금 높게 나오는데, 사람
  검토에서 아주 작은 연기 사진이 빠졌기 때문이다(재현율 61/70 → 64/70, 검증기 AUC 0.90 → 0.92).
  연기색을 탐지 조각으로 잰 것(42/60)과 다시 학습한 모델 비교는 v1 기준 그대로다
- **현장 기기 기준 환경은 개발 노트북을 4코어, 8GB 로 묶어 잰 값이다 (7.3).** 실제 현장 기기에서
  잰 것은 아니다. 메모리는 8GB 안에 들지만 시간은 아래처럼 목표를 넘는다
- **설명 10초 목표는 아직 지키지 못한다.** 설명 한 번은 CPU 4코어에서 10.2초로 목표와 비슷하지만,
  파이프라인 안에서는 검증기가 설명 앞을 막아 탐지 → 설명이 26.6초다(알람이 6번 갱신된 시나리오).
  알람은 설명을 기다리지 않고 1.3초에 나간다
- **핵심 수치의 잡음은 가정이다.** 틀린 단정 3.7% 와 포함률 88~100% 는 가정한 자세 잡음
  아래의 값이다. 잡음 2배 민감도와 같은 확정 비율 비교는 1절에 적었다. 실제 비행의 오차는
  11/23 드론 촬영으로 잰다
- **설명 문장을 사람이 평가한 적이 없다.** 요소 포함률은 낱말이 있는지로 센 값이다

## 제안서와 달라진 점

| 제안서 | 지금 | 이유 |
|---|---|---|
| VLM 은 상황 해설만 (사실 JSON + 템플릿) | 탐지 조각이 연기인지 판정해 위치 개선에도 쓴다 | 11/03 면담 요청. 헛탐지 알람 27 → 13 |
| VLM 사실(연기색, 퍼짐)을 문장에 | 뺀다 | 늘 같은 답보다 못함 |
| 오차 반경 = 드론 위치 오차 + 고도 × tan(기울기) | 카메라 기수와 각도 오차 항 추가 | 포함률 18~72% 로 반경이 정답을 놓침 |
| 시뮬레이터는 추가 목표 | 만들어서 위치 오차 측정의 근거로 씀 | 71330 사진에 촬영 좌표가 없음 |
| 입력 조건 A~D 비교 (6.6) | 생성 방식 3종 비교(4.6)와 반경 판정 효과 직접 측정을 먼저 함. 6.6 은 남음 | 교수님 제안, 정답 좌표가 있어야 핵심 주장을 보일 수 있음 |
| 탐지 모델은 DeepLabv3+ 와 SegFormer 중 선정 | YOLO11n-seg | CPU 4코어에서 가장 빨라 골랐다. SegFormer-B0 과 비교하니 작은 연기(77% 대 57%)와 CPU 시간(133ms 대 340ms)에서 YOLO 가 앞섰다. 학습 조건은 같지 않았고 DeepLabv3+ 는 재지 않았다(`docs/seg_candidates.md`) |
| 반경 내 주거 건물 수 | 반경 내 전체 건물 수 | 건물 자료에 용도 속성이 없다(`docs/buildings.md`) |
| 설명은 탐지 후 10초 이내 | 알람 1.3초, 설명은 CPU 4코어 파이프라인에서 탐지 뒤 26.6초 | 검증기를 더하면서 한 모델이 검증과 설명을 차례로 한다. 위치를 먼저 고치도록 설명을 뒤로 미뤘다(`docs/vlm_compare.md`, `docs/device_measure.md`) |

촬영 데이터로 좌표 오차를 실측하는 것은 제안서에서도 향후 과제로 두었다.
