# 입력 조건 4종 비교 (6.6)

담당: 이수진 / 상태: 측정과 채점 완료

모델에게 주는 정보만 네 단계로 늘려 가며 같은 평가셋 100장의 설명을 받고, 틀린 설명과
과신이 어떻게 달라지는지 비교했다. 제안서 서브골 1의 성공 기준인 "입력 조건 4가지의
환각률, 과신률 비교표"가 이 문서다.

## 무엇을 비교했나

| 조건 | 모델에 주는 것 |
|---|---|
| A | 이미지만 |
| B | A + 탐지 결과 |
| C | B + 오차 반경 안 1순위 용도 |
| D | C + 2순위 용도, 확정·모호·미확정 판정, 오차 반경 |

생성 방식은 (i) 프롬프트만으로 고정했다(`docs/eval_rubric.md`). 생성 방식 비교는 4.6에서
조건 D로 따로 했다(`docs/generation_methods.md`).

## 실험 조건

- 평가셋: 확정본 100장(연기 70, 오탐 유발 30), 정답 `results/eval_facts.jsonl`
- 모델: Qwen2.5-VL-3B-Instruct, 4bit nf4 이중 양자화, 계산 dtype fp16
- 환경: Google Colab T4 GPU, transformers 5.17.0, bitsandbytes 0.50.2
- 프롬프트: `src/vlm/prompts.py` v2. 네 조건이 지시와 예시를 같이 쓰고 정보 블록만 다르다
- 탐지 입력: 100장 모두 같은 값(연기, 신뢰도 0.90, 면적 비율 0.05, 고도 120m).
  정답이 입력으로 새지 않게 하려는 것이다(`src/vlm/eval_alert.py`)
- 생성: 그리디 디코딩, 최대 140토큰, 1회 실행
- 4.6의 조건 D 결과(`results/eval_method_i_v2.jsonl`)는 계산 dtype이 bf16이라 다시 쓰지 않고
  네 조건을 같은 환경에서 새로 돌렸다

```
PILOT_ONE=qwen PILOT_CONDS=A,B,C,D EVAL_DTYPE=fp16 EVAL_RESUME=1 \
EVAL_FACTS=results/eval_facts.jsonl \
python tools/run_pilot.py <평가셋 사진 폴더> results/eval_cond_abcd.jsonl

python tools/score_descriptions.py results/eval_facts.jsonl results/eval_cond_abcd.jsonl
```

## 채점

- 자동(`tools/score_descriptions.py`): 형식 준수, 판정 준수, 과신, 필수 요소 4개, 회피, 환각 중 잘못 봄
- 근거 없는 추론: 설명에 나온 수치와 용도 이름을 각 조건의 입력값과 스크립트로 대조했다.
  입력에 없는 오차 반경, 비율, 용도 이름이 나오면 근거 없는 추론으로 셌다. 화면 구석의
  촬영 시각 표시처럼 사진에 실제로 있는 글자는 제외했다
- 없는 것: 연구자(이수진)가 채점 페이지에서 사진 100장을 대조해 판정했다
- 환각률은 잘못 봄, 없는 것, 근거 없는 추론 중 하나라도 있는 설명의 비율이다

## 결과

| 조건 | 형식 | 환각률 | 연기 사진(70) | 연기 없는 사진(30) | 과신률(43) | 판정 준수(70) | 요소 포함(70) | 회피 |
|---|---|---|---|---|---|---|---|---|
| A | 100% | 64% | 81% (57) | 23% (7) | 0% (0) | 1% (1) | 39% | 26 |
| B | 100% | 99% | 99% (69) | 100% (30) | 2% (1) | 1% (1) | 51% | 1 |
| C | 100% | 93% | 91% (64) | 97% (29) | 0% (0) | 31% (22) | 62% | 0 |
| D | 100% | 33% | 4% (3) | 100% (30) | 49% (21) | 47% (33) | 64% | 2 |

괄호 안은 건수다. 과신률의 분모는 위치 판정이 모호 또는 미확정인 43건이다.

환각 유형별 건수

| 조건 | 잘못 봄 | 없는 것 | 근거 없는 추론 |
|---|---|---|---|
| A | 4 | 10 | 57 |
| B | 31 | 7 | 97 |
| C | 32 | 2 | 85 |
| D | 30 | 0 | 5 |

## 해석

**정보를 덜 주면 모델이 프롬프트 예시로 빈칸을 채운다.** A~C의 근거 없는 추론은 대부분
입력에 없는 오차 반경과 용도 이름이다. "오차 반경 55미터 안이라 제1종일반주거지역일
가능성도 있다. 주거지가 가깝다"처럼 프롬프트 예시 문장을 거의 그대로 옮긴 설명이 많았다.
지시문에 "주어지지 않은 항목은 건너뛴다"가 있어도 지키지 않았다.

**판정과 반경을 주면(D) 지어내는 말은 크게 준다.** 연기 사진의 환각률이 81~99%에서 4%로
떨어졌다. 채울 값이 입력에 있으니 예시를 베낄 이유가 없어진 것으로 본다.

**대신 D에서 과신이 생긴다.** A~C의 과신률이 0~2%인 것은 조심해서가 아니라 단정할 용도
이름이 없거나 1순위 하나뿐이었기 때문이다. D는 두 용도 이름을 모두 받자 모호·미확정 43건 중
21건(49%)에서 이름을 유보 없이 썼고, 판정 규칙은 연기 사진 70장 중 33장(47%)만 지켰다.
4.6의 조건 D, 방식 (i) 결과(판정 일치 51%, 과한 단정 40%)와 같은 수준이다. 지리 정보를
프롬프트로 주고 지시만 하는 방식으로는 과신을 막지 못하며, 이것이 방식 (iii) 구조화 출력과
템플릿(판정 준수 100%, 과한 단정 0%)을 쓰는 근거다.

**탐지가 틀리면 설명으로 고칠 수 없다.** 연기 없는 사진 30장에서 B~D는 29~30장이 연기가
있다고 썼다. 탐지 입력을 100장 모두 "연기"로 고정했기 때문이다. 모델은 사진보다 탐지 결과를
믿었다. VLM 헛탐지 거르기(4.7)를 따로 둔 이유와 같다.

**요소 포함률은 정보와 함께 오른다.** 39% → 51% → 62% → 64%로 늘었고, 회피는 A의 26건에서
B~D는 0~2건으로 줄었다. 다만 A~C에서는 늘어난 요소 상당수가 지어낸 반경과 용도라서,
요소 포함률만으로 개선을 판단하면 안 된다(`docs/eval_rubric.md`의 "환각률을 단독으로
보고하지 않는다"와 같은 이유).

## 한계

- 1회 실행이다. 그리디 디코딩이라 같은 환경에서는 같은 결과가 나오지만, 계산 dtype이나
  라이브러리 버전이 바뀌면 달라질 수 있다
- 탐지 입력을 고정해서 B~D의 "연기 없는 사진" 결과는 실제 파이프라인과 다르다.
  실제로는 탐지가 오탐을 덜 내고, VLM 거르기가 뒤에서 한 번 더 거른다
- 평가셋 위치는 가상 배치라 사진 속 풍경과 입력 용도가 맞지 않는다. 설명의 지리 부분은
  사실 목록 기준으로만 채점했다
- 없는 것은 1인 채점이고 교차 채점을 하지 않아 채점자 간 신뢰도는 확인하지 않았다.
  결론에 쓴 지표는 대부분 입력값과의 자동 대조로 산출했다
- 일부 연기 사진은 연기가 매우 작거나 옅어 축소본에서 잘 보이지 않는다
- 프롬프트 예시 문장이 결과에 크게 영향을 줬다. 예시를 바꾸거나 빼면 A~C의 결과가
  달라질 수 있다
