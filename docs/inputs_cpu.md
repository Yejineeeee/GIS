# 설명 입력 조합별 CPU 시간

GPU 에서 고른 개선(전체 사진과 탐지 조각을 함께 넣기, 불꽃을 따로 묻기)이 현장 기기 기준인
CPU 4코어에서 목표 10초 안에 드는지 쟀다.

담당: 이예진 / 상태: 측정 완료. 기준 환경(8GB 제한, 박서연 7.3)에서 다시 재야 한다

## 방법

`tools/measure_inputs_cpu.py`. `docs/vlm_speed.md`(7.2)와 같은 방식이다.

- llama-server(llama.cpp b12374, 윈도우 CPU 빌드), Qwen2.5-VL-3B Q4_K_M, 스레드 4
- 평가셋에서 탐지가 있는 연기 사진 6장, 조건마다 2번. 조건마다 슬롯 캐시를 비운다
- 조각은 탐지 상자를 모두 감싼 상자 그대로(여백 1배, 최소 96px), 긴 변 1024 까지
- 개발 노트북(Core Ultra 7 155H), 전원 연결, 다른 실험 없이 혼자 돌렸다. 메모리 상한은 걸지 않았다

```
python tools/measure_inputs_cpu.py --eval data/eval_100 --dets runs/verify_real/verify_real.jsonl \
    --out results/inputs_cpu.csv
```

## 결과

| 조건 | 입력 토큰 | 1장 처리 (중앙값) | 최소 ~ 최대 |
|---|---|---|---|
| 탐지 조각만, 세 항목 | 96 ~ 935 | 28.1초 | 2.6 ~ 54.6초 |
| 위 설명 직후 같은 조각에 불꽃 질문 | 25 (사진은 재사용) | **0.7초** | 0.5 ~ 0.8초 |
| 불꽃 질문만 따로 | 53 ~ 892 | 25.3초 | 1.5 ~ 48.9초 |
| 줄인 전체(긴 변 448) + 조각 | 268 ~ 1107 | 37.1초 | 11.9 ~ 61.0초 |
| 사진 전체만 | 861 | 48.0초 | 44.0 ~ 53.1초 |
| 사진 전체 + 조각 | 901 ~ 1740 | 75.1초 | 45.4 ~ 98.0초 |

서버 메모리는 최대 5.19GB 였다. 두 번의 반복은 서로 2~4초 안에서 같았다.

- **시간은 입력 토큰 수에 비례한다.** 토큰 하나에 약 0.053초다. 출력(34토큰)은 거의 영향이 없다
- **불꽃 질문은 설명 뒤에 덧붙이면 0.7초다.** 같은 사진을 다시 처리하지 않기 때문이다.
  따로 물으면 조각을 처음부터 처리해 25초가 든다. 설명과 같은 조각으로, 바로 이어서 물어야 한다
- **전체 사진을 넣는 조합은 모두 목표를 넘는다.** 전체만 48초, 전체 + 조각 75초, 전체를 줄여도 37초다.
  GPU 에서 연기 인식을 64% 에서 81% 로 올린 전체 + 조각 입력(`docs/vlm_crop_views.md`)은 CPU 에서 쓸 수 없다
- **조각만 넣어도 조각이 크면 목표를 넘는다.** 96토큰(108x96)은 3초, 935토큰(1024x642)은 55초다.
  10초 안에 들려면 입력이 약 180토큰, 조각으로는 긴 변 360 안팎이어야 한다

## 7.2 의 9.2초와 다른 이유

`docs/vlm_speed.md` 의 9.2초는 입력 188토큰일 때 값이다. 그때 쓴 6장은 탐지 상자가 작았다.
이번 6장은 탐지 상자를 모두 감싸면 화면의 큰 부분을 차지하는 사진이 섞여 있다. 토큰당 시간도
이번이 더 길다(7.2 는 약 0.040초, 이번은 0.053초). 실행 파일 버전이 다르고, 배터리가 낮은
상태에서 충전하며 쟀다. 절대값보다 조건 사이의 비율을 본다.

## 파이프라인에 주는 뜻

1. 지금 `src/pipeline/vlm_client.py` 의 `observe` 는 사진 전체를 넣는다. CPU 에서는 한 장에 48초다.
   현장 기기에서 10초를 맞추려면 탐지 조각을 넣고 크기 상한을 둬야 한다
2. 조각의 크기 상한을 두면 정확도가 달라질 수 있다. 긴 변 360 으로 줄인 조각에서 연기 유무가
   유지되는지는 재지 않았다
3. 불꽃 질문은 설명과 같은 조각에 이어서 물으면 비용이 거의 없다. CPU 에서도 넣을 수 있는 개선이다
