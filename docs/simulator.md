# 드론 시뮬레이터

실제 지형 위로 가상 드론을 날리고, 아는 좌표에 연기를 피워 프레임을 뽑는다.
탐지와 좌표 변환을 끝까지 이어 시험하려고 만들었다.

담당: 이예진 / 상태: 돌아감. 연기 모양은 더 다듬어야 함

## 왜 만들었나

71330 사진에는 촬영 좌표가 없다. 라벨의 `gps`는 장소마다 하나씩이고 절반이 같은
기본값이라 쓸 수 없다(`docs/data_71330.md`). 그래서 지금까지 지리 쪽 수치는 모두
가상 배치 위에서 낸 것이고, 좌표 변환이 실제로 몇 미터 틀리는지 잴 방법이 없었다.

시뮬레이터는 두 가지를 알고 있어 그 자리를 메운다.

- 카메라의 위치, 고도, 기수 방향, 촬영 각도, 화각
- 화면의 한 점이 지상 어디인지 (`globe.pick`)

연기를 우리가 고른 좌표에 피우므로 발화점의 정답도 안다. 탐지가 낸 좌표와 비교하면
파이프라인 전체의 오차가 나온다.

## 쓰는 법

```
pip install  (없음. 외부 패키지 없이 돈다)
python3 tools/sim_server.py sim 8712
```

브라우저에서 `http://localhost:8712` 를 연다.

| 조작 | |
|---|---|
| W, S | 앞뒤 |
| A, D | 좌우 |
| Q, E | 위아래 |
| 방향키 좌우 | 기수 |
| 방향키 위아래 | 카메라 각도 |
| 자동 비행 | 발화점을 끼고 돈다 |
| 연기 켜기 | 아는 좌표에 연기를 피운다 |
| 프레임 뽑기 | PNG 와 카메라 값을 `sim/frames/` 에 저장 |

`프레임 뽑기`가 내는 JSON 은 `schema/detection.example.json` 의 `camera` 블록과
같은 형식이다. `tools/predict_seg.py` 와 `src/geo/transform.py` 에 그대로 넣을 수
있다.

### 토큰

실제 지형과 위성 영상에는 Cesium ion 토큰이 필요하다. 무료로 받을 수 있다.

1. [cesium.com/ion](https://cesium.com/ion/signup) 가입
2. Access Tokens 에서 기본 토큰 복사
3. `sim/token.js.example` 을 `sim/token.js` 로 복사하고 값을 채운다

토큰 파일은 저장소에 올리지 않는다(`.gitignore`). 토큰이 없으면 평평한 지형과
지도 타일로 뜨고, 그 상태로도 조작과 프레임 뽑기는 된다.

## 찾은 것

### 1. 고도 기준이 안 맞으면 60m 틀린다

`src/geo/transform.py` 는 `camera.alt_ref` 가 `지면` 이 아니면 가정값 120m 를 쓰고
넘어간다. 실제 드론 GPS 는 타원체나 해발 기준으로 고도를 준다.

모래고개입구는 지면이 해발 102.7m 다. 그래서 "타원체 120m" 는 실제로 지면 위
17.3m 다. 이 차이가 지상에서 60.1m 오차로 나타났다.

| 넣은 값 | 결과와 정답의 차이 |
|---|---|
| 타원체 120m 그대로 | 60.1m |
| 지면 기준 17.3m 로 고쳐서 | 0.82m |

**좌표 변환 수식 자체는 맞다.** 고도를 제대로 주면 0.82m 이고, 남은 차이는 지형
기복 때문이다. 고칠 곳은 GPS 고도를 지면 기준으로 바꾸는 단계다. DEM 이 이미
있으므로 `지면 기준 고도 = GPS 고도 - 그 지점 DEM 고도` 로 구할 수 있다.

### 2. 연기가 공중에 떠 있는 것을 셈에 넣지 않아 565m 틀린다

탐지부터 좌표까지 한 번에 돌려 본 결과다.

| | 위도 | 경도 |
|---|---|---|
| 정답 발화점 | 37.733100 | 128.908900 |
| 파이프라인 | 37.737771 | 128.911415 |
| 차이 | 565m (남북 520m, 동서 221m) | |

`transform.py` 는 탐지한 픽셀이 지면 위의 점이라고 보고 광선을 지면까지 늘린다.
그런데 연기는 지면에서 수십 미터 위에 있다. 카메라가 수평에 가까우면(이 경우
-12도) 조금만 위를 봐도 지면까지의 거리가 크게 늘어난다. 드론과 발화점 거리가
562m 인데 계산은 1,104m 가 나왔다.

생각해 볼 수 있는 것이 셋이다.

- 폴리곤의 맨 아래를 대표 픽셀로 쓴다. 연기 밑동이 발화점에 가깝다
- 오차 반경에 `연기 높이 x tan(촬영 각도)` 항을 더한다
- 카메라 각도가 얕으면 거리 추정이 불안정하다고 보고 미확정으로 둔다

**가상 배치로는 이 오차가 보이지 않는다.** 탐지한 픽셀과 좌표가 애초에 연결되어
있지 않기 때문이다. 시뮬레이터라서 드러났다.

### 3. 연기가 옅으면 탐지가 엉뚱한 곳을 잡는다

연기 진하기를 바꿔 가며 같은 자리에서 뽑은 프레임으로 쟀다. 모델은
`runs/smoke_1260_960`, 문턱은 0.10 이다.

| 연기 알파 | 탐지 수 | 연기를 잡았나 | 연기 conf | 헛탐지 최고 |
|---|---|---|---|---|
| 0.014 | 10 | 아니오 | - | 0.510 |
| 0.030 | 0 | 아니오 | - | - |
| 0.060 | 1 | 아니오 | - | 0.379 |
| 0.120 | 1 | 예 | 0.877 | 없음 |
| 0.250 | 1 | 예 | 0.824 | 없음 |

옅게 두면 모델이 연기 대신 밭이나 맨땅을 집는다. 위성 영상을 지형에 입혀 비스듬히
보면 질감이 늘어나 밝고 흐릿해지는데, 그것이 연기처럼 보이는 것으로 짐작한다.

알파 0.12 를 쓴다. 눈으로 보기에 지나치게 진하지 않으면서 연기만 잡고 헛탐지가
없다.

### 4. 창이 뒤에 있으면 지형 값을 못 읽는다

지형 고도와 지상 좌표는 화면에 그려진 타일에서 읽는다. 브라우저 창이 뒤에 있어
렌더가 멈추면 값이 `undefined` 로 나온다. 읽기 전에 몇 번 강제로 그리도록 했다
(`settle()`).

### 5. 탐지가 되는 거리는 연기 크기가 가른다

8주차에 거리 500m 이상에서 한 장도 잡지 못했다고 적었는데, 다시 재 보니 틀렸다.
그때는 연기를 켜고 40초쯤 지나 찍었고, 다시 잴 때는 1분 넘게 기다렸다. 그 사이
기둥이 훨씬 굵어졌고 600m 에서도 잡혔다.

고도 120m 에 거리만 바꿔 찍은 결과다. 거리마다 두 장씩이고, 빈 화면으로 캡처된
한 장은 뺐다.

| 거리 | 잡은 수 | conf | 화면 면적비 | 발화점 밖 탐지 |
|---|---|---|---|---|
| 100m | 1/1 | 0.27 | 1.35% | 2 |
| 150m | 2/2 | 0.61 ~ 0.63 | 1.8% | 4 |
| 200m | 2/2 | 0.55 ~ 0.59 | 1.7% | 2 |
| 250m | 2/2 | 0.63 ~ 0.66 | 1.8% | 0 |
| 300m | 2/2 | 0.77 ~ 0.79 | 6.7% | 8 |
| 400m | 2/2 | 0.55 ~ 0.63 | 4.4% | 6 |
| 500m | 2/2 | 0.70 ~ 0.71 | 3.0% | 0 |
| 600m | 2/2 | 0.46 ~ 0.47 | 0.6% | 0 |

시뮬레이터의 연기는 입자가 계속 쌓여 시간이 갈수록 커진다. 거리만 바꾼 비교를
하려면 연기 크기를 고정해야 하는데, 이번 측정도 그 점에서 거리 효과만 떼어낸
것은 아니다.

가장 낮은 값이 거리 100m 에서 나온 것이 눈에 띈다. 고도 120m 에 거리 100m 면
내려다보는 각이 50도가 되어 기둥이 화면 위로 잘린다. 가까울수록 잘 잡히는 것이
아니다.

다시 재려면 연기를 켜고 1분 넘게 기다린 뒤 아래처럼 한다.

```
브라우저 콘솔에서   await sweep([150, 250, 350, 500], 120)
python tools/detect_range.py sim/frames runs/smoke_1260_960/weights/best.pt 44.7
```

마지막 숫자는 발화점의 지면 높이다. 콘솔에서 `groundHeight(FIRE.lon, FIRE.lat)`
로 읽는다.

### 6. 비닐하우스를 연기로 잡는다

거리 400m 프레임의 오른쪽 아래, 은색 지붕이 줄지어 선 비닐하우스 단지를 연기로
잡았다. conf 0.55 로, 같은 프레임의 진짜 연기(0.63)와 큰 차이가 없다.

71330 의 오탐 유발 분류는 구름, 굴뚝연기, 안개연무 셋뿐이라 비닐하우스는 학습에도
검증에도 들어 있지 않다. `docs/train_results.md` 의 헛탐지 수치에 이것이 빠져
있는 이유다. 시연 지역이 농촌이므로 화면에 실제로 들어온다.

굴뚝을 거를 때 쓴 건물 근접 점수를 그대로 쓸 수 있는지 확인해야 한다. V-World
건물 레이어에 비닐하우스가 들어 있으면 따로 손댈 것이 없다.

### 7. 같은 연기를 여러 조각으로 쪼갠다

거리 300m 프레임에서 탐지가 11개 나왔는데 그중 7개가 같은 기둥이었다. 연기가
클수록 심해진다. `docs/train_results.md` 한계에 적어 둔 현상이 시연 크기에서
그대로 나타난 것이다.

불 하나에 알람이 일곱 개 뜨면 지도에 마커가 일곱 개 찍힌다. 탐지 뒤에 겹치는
폴리곤을 하나로 합치는 처리가 필요하다.

## 시연에 쓸 설정

- 연기를 켜고 1분 넘게 지난 뒤에 시작한다
- 거리 150~500m, 고도 120m 를 쓴다
- 거리 100m 처럼 가까이 가지 않는다. 기둥이 화면 위로 잘린다
- 600m 도 잡히기는 하나 conf 0.46 이고 화면 면적이 0.6% 라 여유가 적다

지금 설정에서 연기는 화면의 1.7~6.8% 를 차지한다. 초기 산불치고 큰 편이므로, 더
작게 피우면 그럴듯해지는 대신 탐지 여유가 줄어든다. 어느 쪽을 택할지 정해야 한다.

## 한계

- 연기 모양이 투박하다. Cesium의 입자는 네모난 판에 그림을 입혀 뿌리는 방식이라,
  소용돌이나 난류가 생기지 않는다. Unreal이나 Blender를 쓰면 나아지지만 지형과
  좌표를 처음부터 다시 붙여야 한다.
- 위성 영상을 비스듬히 보는 것이라 실제 드론 영상과 질감이 다르다. 입체 자료(Google
  Photorealistic 3D Tiles)를 쓰면 해결되지만 한국은 대상이 아니다.
- 위 두 가지 때문에, 탐지 성능 숫자를 이 화면으로 내면 안 된다. 성능은 71330 실제
  사진으로 잰다. 시뮬레이터로 재는 것은 좌표 변환 오차와 파이프라인 연결이다
- 지형이 Cesium World Terrain이고 우리 DEM(90m)과 다르다
