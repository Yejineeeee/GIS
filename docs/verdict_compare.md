# 한 점 조회와 반경 판정 비교 (핵심 주장 검증)

과제의 핵심 주장은 "위치 오차를 고려해 반경 안 용도로 판정하면 틀린 용도를 단정하는
일이 준다"이다. 4.6 의 판정 준수 100% 는 템플릿이 막아서 나온 값이라 이 주장을
보여 주지 못한다. 그래서 정답 좌표가 있는 조건에서 틀린 단정 비율을 직접 쟀다.

담당: 이예진 / 상태: 1차 측정 완료

```
python tools/verdict_compare.py <landuse_5179.geojson> --n 600
```

## 방법

시뮬레이터로 발화점마다 새로 찍으면 연기가 자라는 데만 한 장에 1분이 넘게 걸린다.
그래서 시뮬레이터에서 이미 잰 탐지 오차를 지도 위 여러 발화점으로 옮겨 썼다.

- 발화점 600곳: 시연 지역(모래고개입구 범위, 가장자리 200m 제외) 안 용도지역이 있는
  곳에서 고르게 뽑았다. 바다는 뺐다
- 드론: 발화점에서 아무 방향으로 200~800m 떨어진 고도 120m. 거리와 카메라 각도는
  시뮬레이터 프레임 31장 중 하나에서 가져왔다
- 탐지 픽셀: 정답 픽셀에 그 프레임의 탐지 밑동이 벗어난 만큼을 더했다. V2(검증기
  0.7 통과 중 conf 1등)와 V0(conf 1등), 그리고 탐지 오차가 없는 정답 픽셀을 함께 봤다
- 자세 잡음: 보통(수평 2m, 고도 2m, 기수 2도, 카메라 각도 1도, 1 시그마)
- 좌표와 반경: `src/geo/transform.py`, 판정: `src/pipeline/verdict.py`(반경별 임계값,
  얕은 각도면 미확정), 조회: `src/geo/query.py`. 지형은 V-World DEM 하나로 정답과
  계산을 모두 했다

비교한 방식

| | 방식 |
|---|---|
| C | 한 점 조회. 추정 좌표 한 점의 용도를 그대로 단정한다 (제안서 입력 조건 C) |
| D | 지금 반경으로 조회하고 판정한다 (지금 파이프라인) |
| D+ | 반경에 각도 오차 항을 더하고 판정한다. `2 x sqrt((d sψ)² + (h sθ / sin² dep)² + (sh / tan dep)²)` (`docs/simulator.md` 11/04). transform.py 는 고치지 않고 이 도구 안에서만 계산했다 |

채점은 실제 발화점의 용도를 정답으로 한다. 확정은 1순위가 정답이면 맞는 확정,
아니면 틀린 단정이다. 모호는 1, 2순위 안에 정답이 있으면 맞다. 미확정은 용도를
말하지 않는다.

## 결과

탐지 V2, 600곳

| 방식 | 틀린 단정 | 확정했을 때 정확도 | 확정 | 모호 | 미확정 | 반경 포함률 |
|---|---|---|---|---|---|---|
| C 한 점 조회 | 18.3% | 81.7% | 100% | | | |
| D 지금 반경 | 8.2% | 86.5% | 60.3% | 0% | 39.7% | 21% |
| **D+ 각도 항 반경** | **3.7%** | **92.4%** | 48.2% | 9.7% | 42.2% | 84% |

틀린 단정이 C 18.3% 에서 D+ 3.7% 로 80% 줄었다(차이의 95% 신뢰구간 12.0~17.7%p,
부트스트랩 2,000번).

### 지금 반경(D)은 얕은 각도 규칙 이상을 하지 못한다

D 의 개선은 대부분 600m 이상에서 "내려다보는 각이 15도보다 얕으면 미확정"이라는
규칙에서 나왔다. 600, 800m 는 거의 모두 미확정이 된다. 한 점 조회에 이 규칙만 더한
것(C + 얕은 각도 미확정)과 비교하면 차이가 없다.

| 200~400m, 383곳 | 틀린 단정 | 확정했을 때 정확도 | 확정 | 모호 | 미확정 |
|---|---|---|---|---|---|
| C 한 점 조회 | 14.1% | 85.9% | 100% | | |
| C + 얕은 각도 미확정 | 13.1% | 86.1% | 94.3% | | 5.7% |
| D 지금 반경 | 12.5% | 86.7% | 94.3% | 0% | 5.7% |
| **D+ 각도 항 반경** | **5.7%** | **92.4%** | 75.5% | 15.1% | 9.4% |

판정을 실제로 쓰는 200~400m 에서 지금 반경은 한 점 조회와 거의 같다. 반경이 작아
(평균 200m 13m, 300m 17m, 400m 22m) 반경 안 용도가 한 점 용도와 거의 같기 때문이다.
각도 항을 넣으면 반경이 36m, 56m, 83m 가 된다. 각도 항을 넣으면 틀린
단정이 14.1% 에서 5.7% 로 줄고(신뢰구간 5.2~11.2%p), 그 대가로 15% 를 모호로 낮춘다.
**반경 판정이 효과를 내려면 반경이 실제 오차를 담아야 한다.**

### 거리별 틀린 단정 (C / D / D+)

| 거리 | 곳 | 정답 픽셀 | V0 | V2 | 오차 중앙(V2) |
|---|---|---|---|---|---|
| 200m | 143 | 6 / 6 / 4% | 16 / 17 / 12% | 16 / 15 / 12% | 32m |
| 300m | 126 | 13 / 11 / 4% | 13 / 11 / 5% | 12 / 11 / 2% | 25m |
| 400m | 114 | 12 / 9 / 2% | 18 / 16 / 9% | 14 / 11 / 2% | 32m |
| 600m | 124 | 15 / 2 / 0% | 21 / 1 / 0% | 21 / 1 / 0% | 73m |
| 800m | 93 | 20 / 0 / 0% | 32 / 0 / 0% | 32 / 0 / 0% | 125m |

- 한 점 조회는 멀어질수록 틀린 단정이 는다(V2 200m 16% → 800m 32%)
- 200m 는 D+ 로도 12% 가 남는다. 이 거리에서는 자세 잡음보다 탐지 오차(밑동을 잘못
  짚음)가 크고, 반경 공식은 탐지 오차를 담지 않는다. 정답 픽셀로는 4% 다
- 검증기(V2)는 V0 보다 D+ 틀린 단정을 5.5% 에서 3.7% 로 낮췄다. 400m 에서 차이가
  크다(9% → 2%)

## 정리

- 반경 판정은 한 점 조회보다 틀린 단정을 크게 줄인다(18.3% → 3.7%). 다만 그 효과는
  **각도 항을 넣은 반경**에서만 나온다
- 지금 반경으로는 얕은 각도 규칙을 뺀 효과가 거의 없다. 반경 공식 수정(WBS 3.3)이
  핵심 주장에 필요하다
- 확정했을 때 정확도는 D+ 에서 92.4% 로 목표 95% 에 조금 못 미친다. 탐지 오차가 없으면
  95.6% 다. 남은 차이는 탐지가 밑동을 잘못 짚는 데서 온다
- 틀린 단정을 줄인 대가로 확정이 100% 에서 48% 로 준다. 600m 이상은 사실상 모두
  미확정이므로, 시연과 운영은 400m 안에서 하는 것이 맞다

## 한계

- 탐지 오차는 시뮬레이터 31장의 픽셀 차이를 옮겨 쓴 것이다. 장소가 바뀌면 연기 모양과
  배경이 달라 탐지 오차도 달라질 수 있다
- 정답과 계산에 같은 DEM 을 써서 지형 차이로 생기는 오차는 들어가지 않았다. 실제로는
  더 틀린다(`docs/simulator.md` 11/04, DEM 과 시뮬레이터 지형 차이 600m 에서 94m)
- 잡음이 없어도 얕은 각도에서 오르막을 보면 밑동 높이 2m 때문에 크게 틀리는 경우가
  있다(정답 픽셀, 600m 에서 199.6m). 실제 기하에서도 생기는 일이라 그대로 두었다
- 각도 항의 잡음 크기는 가정이다. 실제 드론 자세 오차가 더 크면 D+ 포함률도 낮아진다
- 용도지역은 법적 구역이라 실제 토지 이용과 다를 수 있다
