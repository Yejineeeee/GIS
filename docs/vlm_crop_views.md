# 전체 사진과 확대 조각을 함께 넣기 (4.7 추가 실험)

전체 사진만 주면 VLM 이 작은 연기를 못 보고, 연기 부분만 잘라 주면 주변이 사라져 굴뚝연기와
구름을 연기라고 한다. 둘을 함께 넣으면 양쪽 장점을 가져가는지 평가셋 100장으로 쟀다.

담당: 이예진 / 상태: 측정 완료, 파이프라인 반영은 팀 논의 필요

## 방법

`tools/vlm_crop_views.py`. 모델(Qwen2.5-VL-3B 4bit), 스키마, 질문은 생성 방식 (iii)
(`tools/run_structured.py`)과 같다. 평가셋 100장(연기 70, 굴뚝연기 15, 구름 15).

| 조건 | 입력 | 자르는 기준 |
|---|---|---|
| A | 전체 사진 | - (`results/eval_method_iii.jsonl` 그대로) |
| B | 조각 | 정답 라벨 |
| C | 전체 사진 + 조각 | 정답 라벨 |
| D | 전체 사진 + 조각 | YOLO conf 1등 탐지 상자 |

- 조각은 상자의 가로세로를 1.5배로 넓혀 자른다. 정답 라벨 조각은 연기 사진이면 연기 라벨,
  연기 아닌 사진이면 그 사진의 구름, 굴뚝연기 라벨을 감싼 상자다
- C 와 D 는 질문 끝에 "사진은 두 장이다. 두 번째 사진은 첫 번째 사진의 일부를 확대한
  것이다."를 붙였다
- D 는 실제 파이프라인과 같은 조건이다. 탐지가 없는 사진은 VLM 을 부르지 않고 "연기 아님"으로
  센다(알람이 뜨지 않는다). 탐지는 `runs/verify_real/verify_real.jsonl` 에서 읽었다
- 전체 사진은 긴 변 1024, 조각은 긴 변 768 로 줄인다

```
python tools/vlm_crop_views.py run B      # C, D 도 같다
python tools/vlm_crop_views.py report
```

결과는 `results/crop_views_B.jsonl`, `_C.jsonl`, `_D.jsonl` 에 있다.

### C 는 양쪽 장점을 가져가는가

- **전체 사진의 장점은 그대로 가져간다.** 연기 아닌 사진 30장의 답이 A 와 같다(17/30).
  조각만 줄 때 구름 15장 중 8장을 연기라고 하던 것이 다시 1장으로 돌아온다
- **조각의 장점은 절반쯤 가져간다.** 연기 사진은 64% → 81% 로 오르지만 조각만 줄 때의
  91% 에는 못 미친다. 면적 0.5% 미만은 1장 → 8장이고 조각만 주면 15장이다
- **굴뚝연기는 어느 입력으로도 못 가른다.** A, B, C 모두 15장 중 12장을 연기라고 한다
- **연기색과 퍼짐은 입력과 무관하고, 이 평가셋으로는 잴 수 없다.** 아래에 따로 적는다

### 연기색과 퍼짐은 잴 수 없는 항목이다

표의 연기색 30~40%, 퍼짐 17% 는 모델이 맞힌 비율이 아니다.

- **모델은 한 가지 답만 한다.** A, B, C 210번의 색 답이 모두 "검은색" 아니면 "없음"이고
  흰색이나 회색은 한 번도 없다. 퍼짐은 "좁음"을 한 번도 답하지 않고 거의 "보통"이다.
  색 정확도는 흑색 라벨 사진의 비율(30/70)이 그대로 나온 것이다
- **색 라벨은 눈에 보이는 색이 아니라 발화원을 따른다.** 라벨은 71330 원본 클래스를 그대로
  가져왔다. 흑색연기 30장은 모두 연막탄(흑색) 사진인데, 조각 4장을 눈으로 보니 연기 대부분이
  옅은 회색이고 검은 부분은 불씨 바로 위뿐이다. 백색회색 라벨의 나뭇잎 연기는 분명한 흰색이다.
  6.2 사람 검토 전이다
- **퍼짐의 정답은 임시 기준이다.** 면적 5% 미만을 좁음으로 두어 70장 중 58장이 좁음이다
  (`tools/score_descriptions.py` 의 구간. 라벨 분포를 보고 다시 맞추기로 한 값이다)

왜 늘 검은색인지 보려고 조각 15장(분명한 흰 연기 10, 흑색 라벨 5)에 묻는 방식을 바꿔 봤다.

| 묻는 방식 | 흰 연기 10장 | 흑색 라벨 5장 |
|---|---|---|
| 구조화 출력, 목록 순서 검은색-회색-흰색 | 검은색 9, 없음 1 | 검은색 5 |
| 구조화 출력, 목록 순서 흰색-회색-검은색 | 검은색 9, 없음 1 | 검은색 5 |
| 번호 고르기, 1 검은색 2 회색 3 흰색 | 회색 10 | 회색 5 |
| 번호 고르기, 1 흰색 2 회색 3 검은색 | 회색 8, 흰색 2 | 회색 4, 흰색 1 |
| 한 단어로 자유롭게 | 흰색 6, 검정 3, 노란색 1 | 검정 3, 흰색 1, 알 수 없음 1 |

- 목록 순서를 바꿔도 구조화 출력의 답은 같다. 목록 맨 앞이라서 검은색을 고른 것이 아니다
- 같은 사진인데 묻는 방식에 따라 검은색, 회색, 흰색으로 답이 갈린다. 번호로 물으면 순서와
  상관없이 2번을 고른다. 모델의 답이 사진보다 질문 형식을 따른다
- 자유롭게 물을 때만 사진에 따라 답이 조금 달라진다(흰 연기 10장 중 흰색 6). 15장이라
  경향만 본 것이다

발표에서 "모델 탓인가 데이터 탓인가"를 물으면 둘 다라고 답한다. 모델은 형식에 따라 같은 답을
내고, 라벨은 색의 정답으로 쓰기 어렵다. 연기색과 퍼짐을 문장에 쓰지 않는다는 결정은 그대로다

### D 에서 얼마나 떨어지는가

D 의 표 숫자에는 YOLO 의 결과가 섞여 있다. 나눠서 본다.

탐지가 있는 사진만 (연기 63장, 굴뚝연기 5장. 구름은 탐지가 없다)

| | A | B | C | D |
|---|---|---|---|---|
| 연기 63장을 연기라고 함 | 43 | 59 | 54 | 52 |
| 굴뚝연기 5장을 연기 아님이라고 함 | 0 | 1 | 0 | 0 |

- **정답 라벨 대신 YOLO 상자로 잘라도 거의 같다.** 탐지가 있는 연기 63장에서 C 54장, D 52장이다
- D 에서 놓친 연기 18장 중 7장은 YOLO 가 탐지하지 못한 사진이라 VLM 과 무관하다
- D 의 "연기 아닌 사진 25/30"은 VLM 이 거른 것이 아니다. 25장 모두 YOLO 가 탐지하지 않아
  VLM 을 부르지 않은 사진이다

### 헛탐지를 걸러 주는가

- **거르지 못한다.** 연기 아닌 사진에 뜬 헛탐지는 굴뚝연기 5장이고, 전체 사진과 조각을
  함께 줘도 5장 모두 연기라고 했다
- 같은 5장에 후보 검증기(P(예) 0.7)를 쓰면 2장이 걸러진다. 헛탐지를 거르는 일은 지금의
  검증기가 더 낫다
- 연기 사진에서 conf 1등이 헛탐지인 7장은 6장을 "연기 아님"이라고 했다. 조각만 보면 맞는
  답이지만 그 사진에는 다른 자리에 연기가 있다. 파이프라인에서는 검증기가 이 경우 다른
  탐지로 위치를 고친다

## 추천

해설 단계의 입력을 "전체 사진 + 탐지 조각"으로 바꾸는 것은 **연기 유무 답을 알람과 맞추는
용도로는 권한다. 헛탐지를 거르는 용도로는 권하지 않는다.** 탐지가 있는 연기 사진에서 VLM 이
"연기 없음"이라고 답하는 경우가 63장 중 20장에서 11장으로 줄어, 알람은 떴는데 설명은 연기가
없다고 하는 어긋남이 절반 가까이 준다. YOLO 상자로 잘라도 정답 라벨로 자른 것과 거의 같아
파이프라인에서 그대로 쓸 수 있다. 대가는 장당 3초쯤(GPU)이고 메모리는 2.77GB 로 4GB 카드에
들어간다. 반면 굴뚝연기 헛탐지는 5장 중 하나도 거르지 못했다. 연기색과 퍼짐은 모델이 늘 같은
답을 내는 항목이라 입력을 바꿔도 달라지지 않는다. 헛탐지는 지금처럼 후보 검증기와 건물 자료로
다루고, 연기색과 퍼짐은 계속 문장에 쓰지 않는다.

## 한계

- 평가셋 100장은 두 장소(모래고개입구, 장현동)다. 연기 아닌 사진 중 탐지가 있는 것은 5장뿐이라
  헛탐지 결과는 장수가 적다
- 조각만 준 이전 결과 파일을 찾지 못해 B 를 같은 기준으로 다시 돌렸다. 이전 기록(연기 89%,
  연기 아닌 사진 30%)과 이번 값(91%, 33%)이 조금 다르다
- 시간과 메모리는 개발 노트북 GPU 값이다. 현장 기기 기준(CPU 4코어)에서는 재지 않았고,
  입력 토큰이 늘어나므로(전체+조각 약 1,100개, 조각만 약 350개) 더 느려진다
- 질문 문장은 한 가지만 시험했다
