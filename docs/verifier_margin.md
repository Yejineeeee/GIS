# 검증기에 주는 조각을 넓혔을 때 (WBS 4.7 ③ 보충)

후보 검증기(`docs/vlm_base_pick.md` ③)는 탐지 박스를 사방 25% 넓힌 조각을 보고 "이 사진에
연기가 있는가"에 답한다. 주변이 거의 안 보여서 헛탐지를 가를 근거가 적을 수 있다고 보고,
조각을 넓히거나 사진 전체를 함께 주면 나아지는지 쟀다. 하는 김에 장소를 섞은 150장에서
AUC 가 0.74 로 떨어지는 이유도 헛탐지 종류별로 나눠 봤다.

담당: 이예진 / 상태: 측정 완료(11/17). 검증기 입력은 바꾸지 않는다

## 왜 했나

- 현장 기기에 소형 GPU 가 있다고 보면, CPU 시간 때문에 미뤄 둔 "넓은 입력"을 다시 볼 수 있다
- 검증기 AUC 가 평가셋에서 0.92, 장소를 섞은 150장에서 0.74 다(`docs/vlm_situation.md`).
  주변을 보여 주면 이 차이가 줄어드는지 알고 싶었다

## 방법

`tools/vlm_verify_margin.py`. 탐지와 정답은 다시 만들지 않고 `tools/vlm_verify_real.py` 가 남긴
박스와 연기 여부를 그대로 읽는다. 입력은 모두 448px 로 맞추므로 조각을 넓혀도 토큰 수는
같다(사진 두 장을 주는 조건만 늘어난다). 모델과 양자화, P(예) 계산은 검증기와 같다.

| 조건 | 입력 | 질문 |
|---|---|---|
| 25% (지금 검증기) | 박스를 사방 25% 넓힌 정사각형 | 이 사진에 연기가 있는가 |
| 100% | 사방 100% (한 변이 박스의 3배) | 같음 |
| 200% | 사방 200% (한 변이 박스의 5배) | 같음 |
| 100% + 상자 | 100% 조각에 탐지 박스를 빨간 선으로 그림 | 빨간 상자 안에 연기가 있는가 |
| 전체 + 조각 | 사진 전체(긴 변 448)와 25% 조각, 두 장 | 두 번째 사진에 연기가 있는가 |

| 세트 | 탐지 | 연기 | 헛탐지 |
|---|---|---|---|
| 평가셋 확정본 100장 | 177 | 131 | 46 |
| 장소를 섞은 150장 | 165 | 135 | 30 |

```
python tools/vlm_verify_margin.py --dets runs/verify_real/verify_real.jsonl \
    --images data/eval_100/images/eval --out runs/verify_margin/eval.jsonl
python tools/vlm_verify_margin.py --dets runs/verify_situation/verify_real.jsonl \
    --images data/situation_150/images/eval --out runs/verify_margin/mix150.jsonl
```

25% 조건의 P(예)는 두 세트 모두 저장돼 있던 검증기 값과 같았다(최대 차이 0.0000).
결과는 `results/verify_margin_eval.jsonl`, `results/verify_margin_mix150.jsonl` 에 탐지마다 한 줄씩 있다.

## 결과

문턱 0.7. "새로 놓친 연기 사진"은 연기 탐지가 있었는데 검증기를 하나도 통과하지 못한 사진이다.

### 평가셋

| 조건 | AUC | 연기 탐지 남김 | 헛탐지 거름 | 새로 놓친 연기 사진 | 입력 토큰 | 1회 (GPU) |
|---|---|---|---|---|---|---|
| **25% (지금)** | **0.916** | 127/131 | **41/46** | 1장 | 295 | 1.8초 |
| 100% | 0.898 | 122/131 | 38/46 | 4장 | 295 | 2.0초 |
| 200% | 0.781 | 101/131 | 37/46 | 5장 | 295 | 1.9초 |
| 100% + 상자 | 0.879 | 127/131 | 13/46 | 1장 | 314 | 2.0초 |
| 전체 + 조각 | 0.904 | 124/131 | 20/46 | 3장 | 468 | 2.6초 |

### 장소를 섞은 150장

| 조건 | AUC | 연기 탐지 남김 | 헛탐지 거름 | 새로 놓친 연기 사진 |
|---|---|---|---|---|
| 25% (지금) | 0.738 | 121/135 | 14/30 | 2장 |
| 100% | 0.719 | 116/135 | 14/30 | 2장 |
| 200% | 0.676 | 102/135 | 18/30 | 6장 |
| 100% + 상자 | 0.728 | 131/135 | 7/30 | 0장 |
| 전체 + 조각 | **0.778** | 128/135 | 10/30 | 1장 |

- **넓힐수록 연기를 놓친다.** 448px 안에서 연기가 작아지기 때문이다. 연기 탐지를 남긴 수가
  평가셋에서 127 → 122 → 101, 150장에서 121 → 116 → 102 로 준다. 헛탐지를 더 거르지도 않는다
- **상자를 그려 주면 "예"로 쏠린다.** 연기는 그대로 남기지만 헛탐지를 13/46, 7/30 만 거른다
- **전체 사진을 함께 주면 순서는 조금 더 잘 매기지만 확률이 전체적으로 높아진다.** 150장에서
  AUC 가 0.738 → 0.778 로 오르는데 문턱 0.7 에서는 헛탐지를 덜 거른다(14 → 10). 쓰려면 문턱을
  다시 정해야 하고, 평가셋에서는 AUC 도 오르지 않는다(0.916 → 0.904)
- **지금 검증기(25%)가 다섯 조건 중 가장 낫다.** 검증기 입력은 바꾸지 않는다

## 0.74 로 떨어지는 이유: 헛탐지의 종류가 다르다

헛탐지를 종류로 나눠 지금 검증기(25%)가 거른 수를 셌다.

| 헛탐지 종류 | 평가셋 | 거름 | 150장 | 거름 | P(예) 중앙값 (평가셋, 150장) |
|---|---|---|---|---|---|
| 연기 사진 속 다른 곳(밭, 맨땅 등) | 40 | 39 | 13 | 11 | 0.29, 0.23 |
| 굴뚝연기 | 6 | 2 | 9 | 3 | 0.99, 0.90 |
| 안개·연무 | 0 | - | 8 | 0 | -, 0.94 |

- **땅 헛탐지는 장소가 바뀌어도 거른다.** 평가셋 39/40, 150장 11/13 이다
- **굴뚝연기와 안개는 거의 통과한다.** 굴뚝연기는 실제로 연기이고 안개는 연기처럼 보인다.
  "연기가 있는가"라는 질문으로는 가를 수 없다
- **150장은 헛탐지 30개 중 17개가 굴뚝연기와 안개다.** 평가셋은 46개 중 6개다. 0.92 와 0.74 의
  차이는 처음 보는 장소라서가 아니라, 이 질문으로 못 가르는 종류가 더 많이 들어 있어서다
- 안개 8개는 전체 사진을 함께 주면 3개를 거른다(지금 검증기는 0개). 안개에는 주변이 조금
  도움이 된다

## 정리

- 검증기 입력은 지금대로 둔다. 넓히거나 전체를 더하는 것으로는 나아지지 않는다
- 검증기가 맡는 일을 "탐지 조각이 연기인지"가 아니라 **"연기가 아닌 땅을 연기로 잡은 헛탐지
  거르기"**로 좁혀 말하는 것이 맞다. 이 일은 두 세트 모두에서 된다
- 굴뚝연기는 건물 자료로 가린다(`docs/chimney_demo.md`). 지금 설계 그대로다
- 안개·연무는 대책이 없다. 질문을 "산불 연기인가"로 바꾸는 것도 아래에서 보듯 실제로 거르는
  수는 늘리지 못했다. 남은 길은 탐지 모델이 안개를 덜 잡게 하는 것(학습 자료)이다

## 질문을 "산불 연기"로 바꾸면 (저장된 결과를 다시 나눔)

`docs/verifier_ffvlm.md` 에서 질문을 ForestFireVLM 의 학습 형식(영어, 11개 항목 중 첫 항목이
"산불에서 나는 연기가 보이는가")으로 바꾸자 150장 AUC 가 0.738 에서 0.836 으로 올랐었다.
"연기"가 아니라 "산불 연기"를 물어서 굴뚝연기와 안개를 가른 것인지 보려고, 그때 저장한
`runs/verify_ffvlm/scores.jsonl` 을 헛탐지 종류로 다시 나눴다. 모델은 새로 돌리지 않았다.
원본 모델(Qwen2.5-VL-3B) 값이고, 평가셋은 그때 쓴 v1(탐지 173개)이다.

| 세트 | 헛탐지 종류 | 수 | 지금 질문 AUC | 거름 | 산불 연기 질문 AUC | 거름 |
|---|---|---|---|---|---|---|
| 평가셋 v1 | 땅 | 41 | 0.97 | 39 | 0.96 | 32 |
| | 굴뚝연기 | 6 | 0.39 | 2 | 0.79 | 2 |
| 150장 | 땅 | 13 | 0.88 | 11 | 0.91 | 11 |
| | 굴뚝연기 | 9 | 0.61 | 3 | 0.80 | 3 |
| | 안개·연무 | 8 | 0.66 | 0 | 0.76 | 0 |

AUC 는 그 종류의 헛탐지와 연기 탐지를 가르는 정도, 거름은 문턱 0.7 에서 걸러낸 수다.

- **순서는 더 잘 매긴다.** 굴뚝연기 AUC 가 0.39 → 0.79, 0.61 → 0.80 으로, 안개가 0.66 → 0.76 으로
  오른다. 전체 AUC 가 오른 것은 이 두 종류 덕이다
- **그런데 실제로 거르는 수는 늘지 않는다.** 굴뚝연기 2/6, 3/9 와 안개 0/8 이 그대로다. 문턱을
  연기 탐지의 95% 를 남기는 값으로 바꿔도 굴뚝연기 1~2개, 안개 0개다. 굴뚝연기와 안개의
  확률이 연기보다 조금 낮아질 뿐 여전히 높아서, 연기를 잃지 않고 가를 문턱이 없다
- **평가셋에서는 땅 헛탐지를 덜 거른다**(39 → 32). 얻는 것 없이 잃는 것이 있다
- 산불 사진으로 미세조정한 모델(ForestFireVLM-3B)도 같은 모습이다. 150장에서 안개를 3개
  거르지만 문턱을 연기 95% 기준으로 잡으면 0개다
- 그래서 질문도 바꾸지 않는다. 한국어로 "산불 연기인가"만 한 줄 묻는 것은 재지 않았다

## 한계

- 종류별 표본이 작다. 굴뚝연기 6개와 9개, 안개 8개다
- 150장 중 117장은 탐지 모델이 학습한 영상이다. 탐지가 달라지면 헛탐지 구성도 달라진다
- 헛탐지를 종류로 나눈 것은 결과를 본 뒤에 한 분석이다. 미리 세운 가설을 확인한 것이 아니다
- 개발 노트북 GPU(4bit nf4)에서 쟀다. CPU 실행 방식(GGUF)으로는 재지 않았다
- 질문을 바꾼 결과는 평가셋 v1 과 영어 학습 형식 질문으로 잰 예전 값을 다시 나눈 것이다
- 조건마다 문턱을 따로 정하지 않고 0.7 을 그대로 썼다. 전체 + 조각은 문턱을 올리면 달라질 수 있다
