# 분할 모델 후보 비교

연기 영역을 찾는 분할 모델을 고른다. 발표할 처리 시간은 현장 기기 기준인 CPU
4코어에서 잰 값이다. GPU 값은 개발 중 반복 실행 속도를 보기 위한 참고다.

담당: 이예진 / 상태: 완료. 정확도 비교까지 끝났고 YOLO11n-seg를 그대로 쓴다

## 측정 결과

입력 640, 이미지 1024x768, 중앙값 9회.

| 모델 | 파라미터 | 연산량 | 파일 | CPU 4코어 | GPU |
|---|---|---|---|---|---|
| YOLO11n-seg | 2.88M | 10.0 GFLOPs | 5.9MB | 82ms | 18ms |
| YOLOv8n-seg | 3.41M | 12.1 GFLOPs | 6.7MB | 107ms | 14ms |
| YOLO11s-seg | 10.11M | 33.4 GFLOPs | 19.7MB | 141ms | 21ms |
| YOLOv8s-seg | 11.82M | 40.3 GFLOPs | 22.8MB | 230ms | 15ms |
| YOLO11m-seg | 22.42M | 114.0 GFLOPs | 43.3MB | 519ms | 36ms |

측정값은 `results/seg_model_compare.csv`에 있다. 다시 재려면
`python tools/compare_seg_models.py 이미지경로`.

## 측정 방법

처음 잰 값은 쓸 수 없었다. 22M 모델이 2.9M 모델보다 빠르게 나왔다. 원인은 두
가지였다. 측정 중간에 가중치를 내려받았고, 이미지를 매번 디스크에서 읽었다.

고친 방법
- 가중치를 모두 먼저 내려받은 뒤에 잰다
- 이미지를 미리 메모리에 올린다
- 추론 시간만 쓰고 전처리와 후처리는 따로 적는다
- 장치마다 모델을 새로 만들고 장치별로 몰아서 잰다

고친 뒤에는 연산량이 커질수록 시간이 늘어나는 순서가 맞았다.

## 선정

**YOLO11n-seg를 1순위로 한다.**

1. CPU 4코어에서 82ms로 가장 빠르다. 후보 중 유일하게 100ms 아래다.
2. 파일이 5.9MB로 가장 작다.
3. 같은 세대 s 모델보다 연산량이 3분의 1인데 CPU 시간은 40% 수준이다.

GPU만 보면 YOLOv8n이 더 빠르지만, 우리가 발표할 조건은 CPU다. GPU 차이 4ms는
현장 기기와 무관하다.

## 정확도 비교 결과

실제 데이터 1,260장으로 n과 s를 각각 학습했다. 자세한 것은
`docs/train_results.md`에 있다.

| | yolo11n @960 | yolo11s @640 |
|---|---|---|
| 분할 mAP50 | 0.559 | 0.510 |
| 파라미터 | 2.88M | 10.11M |

헛탐지율을 맞춰 놓고 작은 연기 탐지율을 비교해도 모든 지점에서 n이 앞섰다.

| 배경 헛탐지 | yolo11n @960 | yolo11s @640 |
|---|---|---|
| 약 2% | 73% | 54% |
| 약 11% | 96% | 91% |
| 약 19% | 98% | 96% |

**n이 밀리지 않았으므로 바꾸지 않는다.** 1,260장으로 10M 파라미터를 채우기에는
데이터가 모자란 것으로 본다. 데이터가 크게 늘면 다시 볼 일이다.

## 다루지 않은 대안

RTMDet-Ins-tiny는 Apache 2.0이라 라이선스가 자유롭다. mmdetection 설치가
Windows에서 까다로워 이번에는 재지 않았다. 라이선스 때문에 바꿔야 하는 상황이
오면 이쪽을 본다. 다만 RTMDet도 YOLO와 같은 개체 분할이라 아래 문제는 그대로다.

**비교한 후보가 모두 개체 분할이다.** 개체 분할은 사물을 하나씩 세는 방식인데
연기는 셀 수 있는 사물이 아니다. 실제로 학습한 모델이 연기 덩어리 하나를 세 조각
으로 쪼개서 낸 경우가 있었다. 픽셀마다 연기인지만 정하는 의미 분할(SegFormer,
U-Net, DeepLabv3+)이 더 맞을 수 있는데 재 보지 않았다.

우리 쓰임새에서는 개수가 중요하지 않아 조각이 나뉘어도 면적을 합치고 중심을 잡으면
된다. 다만 비교하지 않았다는 것은 한계로 남는다. 비교한다면 선정 기준이 CPU 4코어
100ms였으므로 속도부터 재는 것이 순서다.

## 라이선스

ultralytics는 AGPL-3.0이다. 수업 과제와 연구 목적에는 문제가 없으나 상업적으로
쓰려면 별도 허락이 필요하다. Qwen2.5-VL-3B도 같은 상황이므로, 최종 결과물을
상업적으로 쓸 수 없다는 점을 한곳에 적어 둔다.
