# 확정, 모호, 미확정 판정 (WBS 3.6)

오차 반경 안의 용도 비율을 보고, 그 용도를 알람과 설명에 단정해도 되는지 3단계로 정한다.
5.2 파이프라인의 임시 판정을 정식 판정으로 바꾼다.

담당: 이수진 / 상태: 구현과 예시 확인 완료. 100m 초과 반경 처리와 목표 정확도는 팀 확인 필요

## 쓰는 법

```python
from judge import judge, judge_detail
verdict, threshold = judge(land_use, radius_m, coverage, shallow)
detail = judge_detail(land_use, radius_m, coverage, shallow)   # 판정 이유까지
```

| 입력 | 어디서 오나 |
|---|---|
| `land_use` | `query()`의 용도 비율 목록 (3.4) |
| `radius_m` | `transform()`의 `position.error_radius_m` (3.3) |
| `coverage` | `query()`의 `info.landuse_coverage` |
| `shallow` | `transform()`의 `info.shallow` (내려다보는 각 15도 미만) |

`src/pipeline/verdict.py`는 이 파일을 그대로 가져다 쓰도록 바꿨다. 그래서 `run.py`와
`tools/verdict_compare.py`는 고칠 것이 없다.

## 판정 순서

위에서부터 보고, 걸리면 거기서 끝낸다.

| 순서 | 조건 | 판정 | 이유 |
|---|---|---|---|
| 1 | 조회 결과 없음 | 미확정 | 말할 용도가 없다 |
| 2 | 내려다보는 각이 얕음 | 미확정 | 위치 자체를 믿기 어렵다 (3.3, 시뮬레이터에서 565m 오차) |
| 3 | 용도지역이 원의 60% 미만만 덮음 | 미확정 | 나머지가 바다나 자료 밖이라 비율을 믿기 어렵다 |
| 4 | 반경이 100m 초과 | 미확정 | 3.5에서 재지 않은 반경이라 임계값 근거가 없다 |
| 5 | 1순위 비율 ≥ 반경별 임계값 | 확정 | 3.5 최다비율 규칙 |
| 6 | 용도 2개 이상, 1·2순위 합 ≥ 0.9 | 모호 | "A 또는 B"로 말한다 |
| 7 | 그 밖 | 미확정 | |

## 임계값 표

3.5 모의 실험(`docs/threshold.md`)의 최다비율 규칙 결과다. 기본은 목표 정확도 95%이고,
`target=90` 또는 `target=99`로 바꿀 수 있다.

| 반경 | 90% | **95% (기본)** | 99% |
|---|---|---|---|
| 10m | 0.00 | **0.00** | 0.77 |
| 30m | 0.00 | **0.57** | 0.83 |
| 50m | 0.56 | **0.72** | 0.87 |
| 100m | 0.64 | **0.80** | 0.92 |

- 표 사이 반경은 가까운 두 값 사이를 직선으로 잇는다. 예: 75m → 0.76
- 10m보다 작은 반경은 10m 값을 쓴다

## 5.2 임시 판정에서 바뀐 것

| | 임시 (5.2) | 정식 (3.6) |
|---|---|---|
| 100m 초과 반경 | 100m 임계값 0.80을 그대로 씀 | **미확정** |
| 목표 정확도 | 95%만 | 90, 95, 99% 중 고를 수 있음 |
| 판정 이유 | 없음 | `judge_detail()`이 이유를 돌려줌 |

나머지 규칙(얕은 각, 60% 덮음, 모호 기준 0.9)은 그대로다.

### 100m 초과를 미확정으로 둔 이유

자세 오차 항(PR #26)을 넣은 뒤로 반경이 거리 400m에서 약 90m, 600m에서 약 165m,
800m에서 약 263m까지 커진다. 3.5 결과를 보면 반경이 커질수록 같은 정확도를 지키는 데
더 높은 임계값이 필요하다(0.57 → 0.72 → 0.80). 그래서 100m 값을 그보다 큰 반경에
그대로 쓰면 목표 정확도를 지킨다는 근거가 없다.

`docs/verdict_compare.md`에서도 600m 이상은 얕은 각 규칙으로 거의 모두 미확정이 나오고,
시연과 운영은 400m 안에서 하는 것이 맞다고 정리했다. 그래서 이 규칙으로 바뀌는 경우는
400m 근처에서 반경이 100m를 조금 넘는 경우뿐이다.

더 큰 반경에서도 확정을 내야 한다면, 3.5 실험을 150m, 200m로 늘려 임계값을 새로 구하고
`THRESHOLDS` 표에 줄을 더하면 된다. 코드는 고칠 것이 없다.

## 확인한 것

`python3 src/geo/judge.py` 예시 10개 모두 기대한 판정이 나왔다.

| 예시 | 판정 | 이유 |
|---|---|---|
| 한 용도 85%, 반경 50m | 확정 | 0.85 ≥ 0.72 |
| 60% + 35%, 반경 50m | 모호 | 합 0.95 ≥ 0.9 |
| 60% + 35%, 반경 20m | 확정 | 0.60 ≥ 0.285 (10m와 30m 사이 직선) |
| 45 / 30 / 25%, 반경 50m | 미확정 | 0.45 < 0.72, 합 0.75 < 0.9 |
| 한 용도 85%, 반경 165m | 미확정 | 표보다 큰 반경 |
| 한 용도 85%, 얕은 각 | 미확정 | 얕은 각 |
| 한 용도 85%, 원의 40%만 자료 | 미확정 | 60% 미만 |

## 한계

- 임계값은 모래고개입구 범위에서 구한 값이다. 시연 지역이 바뀌면 3.5를 그 지역 용도지역으로
  다시 돌려야 한다 (`tools/threshold_main.py`, 범위만 바꾸면 됨)
- 판정은 위치를 믿을 수 있는지만 본다. 탐지가 틀린 경우(헛탐지)는 막지 못한다
  (`docs/pipeline.md` 5.2 확인 결과). 탐지 신뢰도를 판정에 넣을지는 팀 결정 전이다

## 남은 것

- 팀에서 목표 정확도(90, 95, 99%) 정하기. 지금은 95%
- 100m 초과 반경을 미확정으로 둘지, 3.5를 늘려 임계값을 더 구할지 정하기
- 6.5 오차 반경별 판정 결과 정리에서 이 판정으로 평가셋 결과를 다시 낸다
