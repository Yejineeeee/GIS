# 탐지 정밀도·재현율·F1과 연기 밑동 위치 오차

6.4(`docs/detect_eval.md`)는 IoU, 재현율, 헛경보를 쟀다. 외부 검토에서 정밀도·재현율·F1 과,
위치 계산의 출발점인 연기 밑동의 오차가 평가되지 않았다는 지적이 있어 같은 평가셋으로 쟀다.

담당: 이예진 / 상태: 측정 완료(11/27)

## 방법

`tools/eval_base.py`. 평가셋 확정본 100장(연기 70, 오탐 유발 30), 탐지 모델 `smoke_1260_960`, 운영 문턱 conf 0.10.
마스크와 정답 분류(흑색연기, 백색/회색연기, 화염)는 `tools/eval_detect.py` 와 같다.

- 연기 단위: 탐지 마스크와 정답 연기 마스크를 IoU 가 큰 쌍부터 하나씩 짝짓는다. 짝지은 탐지는 TP, 남은 탐지는 FP,
  남은 정답은 FN
- 사진 단위: 탐지가 하나라도 있으면 "연기 있음"으로 본다
- 밑동 오차: 짝지은 쌍(IoU 0.25 이상)마다, 파이프라인과 같은 방법(`transform.target_pixel`, 폴리곤 아래 5% 점들의 가운데)으로
  탐지 밑동과 정답 밑동을 구해 거리를 잰다

## 결과

| 단위 | TP | FP | FN | 정밀도 | 재현율 | F1 |
|---|---|---|---|---|---|---|
| 연기 하나, IoU 0.5 | 51 | 126 | 51 | 0.29 | 0.50 | 0.37 |
| 연기 하나, IoU 0.25 | 65 | 112 | 37 | 0.37 | 0.64 | 0.47 |
| **사진 한 장** | 65 | 5 | 5 | **0.93** | **0.93** | **0.93** |

- 사진 단위(알람이 나가느냐)로는 0.93 이다. 연기 단위 정밀도가 낮은 것은 한 연기를 여러 조각으로 나눠 잡거나,
  연기 사진 안의 다른 곳을 잡는 탐지가 많기 때문이다. 알람은 사진마다 하나로 묶이고 VLM 검증기가 이런 탐지를 거른다
  (`docs/verifier_ablation.md`: 헛탐지가 위치를 정하는 사진 22장 → 1장)
- 사진 단위 재현율 65/70 은 6.4 의 64/70 과 다르다. 6.4 는 탐지가 연기와 겹쳐야 세고, 여기서는 탐지가 있기만 하면 센다

### 연기 밑동 오차 (짝지은 65쌍)

| | 중앙값 | 90% | 최대 |
|---|---|---|---|
| 거리 (원본 픽셀) | 29 | 299 | 800 |
| 거리 (사진 높이 대비) | 2.0% | 15.6% | 39.0% |
| 세로 거리 (사진 높이 대비) | 0.8% | 4.7% | |

- 탐지 밑동이 정답보다 위에 있는 쌍이 46, 아래가 18 이다. 위로 어긋나면 더 먼 곳으로 계산된다(거리 과대 쪽으로 치우침)
- 세로 오차가 거리 오차로 이어진다. 예를 들어 드론 카메라(가로 화각 67도, 4:3)로 고도 120m 에서 300m 떨어진 연기를 보면
  세로 0.8% 는 약 7m, 4.7% 는 약 38m 다. 600m 에서는 24m, 135m 다. 평가셋 사진은 화각을 몰라 실제 미터로 바꾸지 못했다
- 큰 오차(가로 수백 픽셀)는 넓게 퍼진 연기에서 탐지가 정답과 다른 쪽 끝을 밑동으로 잡은 경우다
- 지금 반경 공식에는 이 밑동 오차 항이 따로 없다. 시뮬레이션에서는 탐지 밑동 오차가 오차의 대부분이었다
  (`docs/radius_tightness.md` 가정 실험). 밑동 오차를 반경에 넣는 것은 향후 과제로 둔다

결과 파일: `results/eval_base_report.json`, 쌍별 오차 `results/eval_base_errors.jsonl`

python tools/eval_base.py data/eval_100_v2 runs/smoke_1260_960/weights/best.pt --out runs/eval_base
