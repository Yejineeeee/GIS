# 설명 평가 기준

경량 VLM이 만든 상황 설명을 채점하는 기준이다. 채점 기준이 흔들리면 결과를 다시
만들어야 하므로 채점 전에 확정한다.

담당: 이예진 / 상태: 채점기가 이 기준대로 돌아가는 것까지 확인

## 무엇을 비교하나

비교 축이 둘이다.

**정보량** 모델에게 주는 정보를 네 단계로 나눈다.

| 조건 | 모델에 주는 것 |
|---|---|
| A | 이미지만 |
| B | 이미지 + 탐지 결과 |
| C | B + 오차 반경 안 1순위 용도 |
| D | C + 확정, 모호, 미확정 판정과 오차 반경 |

**생성 방식** 설명을 만드는 방법을 세 가지로 나눈다. `docs/generation_methods.md`에
있다.

| 방식 | 내용 |
|---|---|
| (i) 프롬프트만 | VLM이 문장을 직접 쓴다 |
| (ii) 규칙 검증 후 재생성 | 쓴 문장을 검사하고 위반이면 다시 쓴다 |
| (iii) 구조화 출력과 템플릿 | VLM은 사실만 내고 문장은 규칙이 조립한다 |

두 축을 모두 곱하면 12가지가 되어 너무 많다. 정보량 비교는 (i)로 네 조건을 비교하고,
생성 방식 비교는 조건 D로 고정해 세 방식을 비교한다.

## 평가를 둘로 나눈다

방식 (iii)은 문장을 규칙이 만든다. 같은 자로 (i)과 비교하면 과신률이 구조적으로 0이
되어 (iii)이 당연히 이긴다. 역할이 다르므로 재는 것도 나눈다.

| 대상 | 무엇을 재나 | 쓰는 지표 |
|---|---|---|
| VLM이 맡은 부분 | 영상에서 본 사실이 맞는가 | 환각률, 사실 정확도, 형식 준수율 |
| 규칙이 맡은 부분 | 판정에 맞는 표현이 들어갔는가 | 판정 준수율, 과신률, 요소 포함률, 회피 |

방식 (i)과 (ii)는 VLM이 문장까지 쓰므로 두 부분을 한 문장에서 읽어야 한다. 방식
(iii)은 VLM 출력이 JSON이고 문장은 규칙이 만들므로 따로 잰다.

### 방식별로 무엇을 보나

| | (i) | (ii) | (iii) |
|---|---|---|---|
| VLM 출력 | 문장 | 문장 | JSON 5항목 |
| 사실 채점 대상 | 문장에서 읽어냄 | 문장에서 읽어냄 | 항목별로 바로 비교 |
| 표현 채점 대상 | 같은 문장 | 같은 문장 | 규칙이 만든 문장 |
| 재생성 횟수 | 없음 | 기록한다 | 없음 |

방식 (ii)는 재생성 횟수를 같이 기록한다. 몇 번을 다시 써야 규칙을 지키는지가
그 방식의 비용이다.

## 사실 정확도 (방식 iii 전용)

방식 (iii)의 VLM 출력은 항목이 정해져 있으므로 항목별로 맞았는지 바로 센다.

| 항목 | 정답과 비교하는 법 |
|---|---|
| smoke_present | 라벨에 연기가 있으면 참 |
| smoke_color | 라벨 클래스가 허용하는 색이면 맞은 것 |
| spread | 라벨 면적 비율로 구간을 정해 비교한다 |
| flame_visible | 라벨에 화염이 있으면 참 |
| terrain | 사람이 본다. 자동으로는 정답이 없다 |

색은 라벨 클래스가 하나로 정해 주지 않는 경우가 있어 허용 집합으로 둔다. 흑색연기는
`검은색`, 백색및회색연기는 `회색`과 `흰색`을 모두 맞은 것으로 센다.

퍼짐 구간은 면적 비율로 자른다. 0.05 이하는 좁음, 0.20 이하는 보통, 그보다 크면
넓음이다. 지금 값은 파일럿에서 쓴 임시 기준이고, 실제 라벨의 면적 분포를 보고 다시
맞춘다.

terrain은 자동 정답이 없으므로 항목별 일치율은 네 항목만 내고, 네 항목을 모두 맞은
비율을 함께 낸다. terrain은 `results/scores.csv`의 `VLM.지형` 칸을 사람이 채운다.

정답 파일에 `class`만 있으면 smoke_present와 smoke_color까지만 채점된다. spread와
flame_visible까지 채점하려면 `area_ratio`와 `flame`이 있어야 한다. 없으면 그 항목은
빈 칸으로 두고 분모에서 뺀다.

## 판정 준수율

판정에 따라 정해진 표현이 들어갔는지 본다. 세 방식에 모두 적용한다.

| 판정 | 지켜야 할 것 |
|---|---|
| 확정 | 1순위 용도 이름을 쓴다 |
| 모호 | 1순위와 2순위를 같이 쓰고 유보 표현을 붙인다 |
| 미확정 | 용도 이름을 쓰지 않고 오차 반경만 쓴다 |

세 가지를 모두 지킨 건수의 비율이다. 방식 (iii)은 100%가 나와야 하고, 그렇지 않으면
템플릿 구현에 문제가 있는 것이다.

규칙은 `src/vlm/verify.py`의 `check()` 한 곳에만 둔다. 방식 (ii)가 재생성 여부를
정할 때 쓰는 검사와 채점기가 쓰는 검사가 같은 코드라야, 통과시킨 문장이 채점에서
위반으로 잡히는 일이 없다.

연기가 없는 사진은 분모에서 뺀다. 알람이 뜰 상황이 아니므로 위치를 설명할 이유가
없고, 같은 이유로 필수 요소 포함률과 회피도 연기가 있는 사진만 센다. 연기가 없는
사진에서 "연기가 관측되지 않았다"는 맞는 답인데 요소 수가 적어 회피로 잡힌다.
`results/scores.csv`의 `연기있음` 칸이 0이면 규칙 쪽 칸은 모두 비어 있다.

## 지표

### 1. 환각률

입력에서 확인되지 않는 내용을 사실로 쓴 설명의 비율이다.

- 분모: 형식을 지킨 설명 건수
- 분자: 환각 문장이 하나 이상 있는 설명 건수

환각 문장은 세 가지로 나눠 센다. 하나라도 있으면 환각 건이다.

| 유형 | 내용 | 예 |
|---|---|---|
| 잘못 봄 | 이미지에 있는 것을 다른 것으로 말함 | 연기를 불꽃이라고 함 |
| 없는 것 | 이미지에도 입력에도 없는 것을 있다고 함 | 비가 내린다, 표시물이 있다 |
| 근거 없는 추론 | 입력에 없는 원인, 수치, 지명을 단정 | 입산자 실화로 보인다, 풍속 5m |

환각으로 보지 않는 것
- 입력 JSON에 있는 값을 그대로 옮긴 경우
- 이미지에서 눈으로 확인되는 것을 적은 경우

보조 지표로 유형별 건수와 설명 1건당 환각 문장 수도 센다.

### 2. 과신률

위치가 확실하지 않은데도 단정해서 말한 비율이다. 이 연구가 줄이려는 값이다.

- 분모: 위치 판정이 모호 또는 미확정인 건수
- 분자: 그중 용도지역 이름을 유보 표현 없이 말한 건수

처음에는 단정 표현 목록에 걸리는지로 정하려 했으나 쓸 수 없었다. `~이다`가 한국어
평서문의 기본형이라 거의 모든 설명이 과신으로 잡힌다. 채점기를 만들면서 바꿨다.

바뀐 기준은 **무엇을 단정했는지**를 본다. 위치가 모호하거나 미확정인데 용도지역
이름을 말하면서 유보 표현을 하나도 붙이지 않았으면 과신이다. 이름을 말하지 않았거나
유보 표현을 붙였으면 과신이 아니다.

조건 A와 B에는 판정이 입력으로 들어가지 않는다. 채점할 때는 같은 이미지에 대해
계산된 판정을 기준으로 분모를 잡는다. 모델이 판정을 못 받았다는 것은 변명이 되지
않고, 그 차이를 보는 것이 실험의 목적이다.

### 3. 필수 요소 포함률

설명에 들어가야 하는 네 가지가 몇 개 들어갔는지 센다. 건별로 0에서 4까지 매기고
평균을 4로 나눈다.

| 요소 | 인정 기준 |
|---|---|
| 무엇 | 정답 클래스와 일치하는 이름을 씀. 연기를 화염이라고 하면 인정하지 않는다 |
| 어디 | 용도지역 이름 또는 좌표를 명시 |
| 위험 대상 | 산림, 주거지, 건물, 도로, 농경지, 시설 중 하나를 명시. 땅, 토양, 지면, 바닥은 인정하지 않는다 |
| 불확실성 | 오차 반경 수치 또는 유보 표현을 명시 |

### 3-1. 회피 건수

요소가 1개 이하인 설명은 회피로 센다. 틀린 말을 안 해서 환각률이 좋아지는 경우를
가려내기 위한 것이다.

### 4. 형식 준수율

지정한 JSON 형식으로 답한 비율이다. `description` 하나만 있는 객체로 파싱되면
준수로 본다. 코드 블록 기호가 붙어 있어도 안쪽이 파싱되면 준수로 본다.

형식을 안 지킨 건은 이 지표에만 넣고 나머지 세 지표의 분모에서 뺀다. 문장이
미완성이면 환각인지 판단할 수 없기 때문이다. 조건별로 몇 건을 뺐는지 결과 표에
같이 적는다.

## 유보 표현 목록

과신률 채점이 사람마다 달라지지 않도록 유보 표현을 목록으로 고정한다. 목록에 없는
표현이 나오면 채점을 멈추고 셋이 합의해 목록에 추가한 뒤 그 시점까지 채점한 건을
다시 본다.

- `추정`, `가능성`, `보인다`, `보입니다`, `확인이 필요`, `중 하나`,
  `일 수 있`, `것으로 판단`, `불확실`, `알 수 없`

목록은 `src/vlm/verify.py`의 `HEDGE` 한 곳에만 둔다. 채점기와 방식 (ii)의 검사가
그 값을 가져다 쓴다. 전에는 채점기에 같은 목록을 따로 적어 두었는데 `알 수 없`이
한쪽에만 들어가 두 목록이 어긋났다. 목록을 고칠 때는 `verify.py`와 이 문서를 함께
고친다.

단정 표현은 목록으로 두지 않는다. 유보 표현이 하나도 없으면 단정으로 본다.

## 자동으로 세는 것과 사람이 보는 것

`tools/score_descriptions.py`가 자동으로 채우는 칸과 사람이 채워야 하는 칸이 다르다.
사람을 빼려는 것이 아니라 사람이 볼 건수를 줄이려는 것이다.

| 항목 | 자동 | 이유 |
|---|---|---|
| 형식 준수 | 자동 | JSON 파싱 여부 |
| 스키마 준수 | 자동 | 방식 (iii)의 출력이 다섯 항목을 다 채웠는지 |
| 사실 정확도 4항목 | 자동 | 라벨 클래스, 면적 비율, 화염 여부와 대조한다 |
| 사실 정확도 terrain | 사람 | 라벨에 지형 정답이 없다 |
| 판정 준수 | 자동 | `verify.py`의 규칙을 그대로 적용한다 |
| 필수 요소 4개 | 자동 | 정답 클래스 이름, 용도지역 이름, 위험 대상 단어, 오차 반경 수치나 유보 표현을 글자로 찾는다 |
| 회피 | 자동 | 요소 수가 1 이하 |
| 환각 중 잘못 봄 | 자동 | 정답과 다른 클래스 이름이 나왔는지 |
| 과신 | 자동 | 판정과 용도 이름, 유보 표현으로 정한다 |
| 환각 중 없는 것 | 사람 | 이미지에 없는 것을 말했는지는 글자로 알 수 없다 |
| 환각 중 근거 없는 추론 | 사람 | 원인이나 날씨를 지어냈는지 판단이 필요하다 |

사람이 볼 것은 `results/scores.csv`의 설명 칸이고, 환각 두 유형만 보면 된다.
나머지는 채워져 있다.

## 채점 방법

1. 평가셋 100장 x 생성 방식 3종 = 300건(`results/scores.csv`)을 조건과 모델 정보를 지운 채 섞어서 채점표에 넣는다. 채점자는 그 설명이
   어느 조건에서 나왔는지 모르는 상태로 채점한다.
2. 두 사람이 각각 채점한다.
3. 두 사람의 결과가 다른 건만 세 번째 사람이 보고 정한다.
4. 채점자 사이 일치율을 기록한다. 0.6 미만이면 기준 문장을 고치고 다시 채점한다.

`tools/make_score_sheet.py`로 채점표를 만들면 조건 열이 가려진 상태로 나온다.

### 채점기 돌리는 법

출력 파일을 여러 개 받아 한 번에 채점한다. 정보량 비교와 생성 방식 비교를 같은
기준으로 봐야 하므로 세 방식을 한 번에 넣는다.

```
python tools/score_descriptions.py results/eval_facts.jsonl \
    results/method_i.jsonl results/method_ii.jsonl results/method_iii.jsonl
```

줄 하나에 `cond`와 `method`가 있어야 어느 칸에 들어갈지 정해진다. `method`가 없으면
방식 (i)로 본다. 정답 파일의 판정과 출력 줄에 적힌 판정이 다르면 그 줄을 알려 준다.
다른 알람으로 돌린 결과를 섞으면 판정 준수율이 뜻을 잃기 때문이다.

결과는 `results/scores.csv`와 집계표 세 개다. 집계표는 정보량 비교, 생성 방식 비교,
사실 정확도다. CSV 열 이름은 `VLM.`과 `규칙.`으로 시작해 어느 쪽을 재는 칸인지
구분한다.

**환각률을 단독으로 보고하지 않는다.** 조건 D는 미확정일 때 용도 이름을 쓰지 말라고
지시하므로, 지시를 따르면 말수가 줄고 환각률이 자동으로 내려간다. 말을 덜 해서
내려간 것과 제대로 판단해서 내려간 것을 구분해야 한다.

읽는 규칙

- 환각률이 내려가고 요소 포함률이 유지되면 개선이다.
- 환각률이 내려갔지만 요소 포함률도 내려갔으면 개선이 아니다. 회피다. 그렇게 적는다.
- 방식 (iii)의 판정 준수율이 100%인 것은 성과가 아니라 설계상 당연한 결과다. 비교할
  것은 그 대가로 사실 정확도나 문장 자연스러움이 떨어졌는지다.
