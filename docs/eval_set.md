# 평가셋 100장 (WBS 6.1)

설명 품질(6.2)과 오차 반경별 판정(6.5)을 잴 때 쓰는 평가셋과, 사진마다 정답이 되는 사실 목록이다.

담당: 이수진 / 상태: 6.2 사람 검토 반영 (확정본). 통과 100

## 만드는 법

```
python3 tools/make_eval_set.py <VL.zip> <landuse_5179.geojson> <buildings_5179.geojson> \
    <37808.img> <37804.img>
```

- 같은 명령을 다시 돌리면 같은 100장이 나온다 (난수 시드 42).
- 사진 꺼내기: `python3 tools/extract_71330.py docs/eval_set.csv <VS.zip> <VL.zip> data/eval_100`

## 고른 기준

- AI Hub 71330 Validation에서 시연 지역 두 곳(모래고개입구, 장현동)만 썼다. 학습용 1,260장에는 이 두 곳 사진이 0장이라 학습과 겹치지 않는다.
- 드론 촬영분만, 영상 하나당 1장만 골랐다 (비슷한 장면이 몰리지 않게).
- 연기 70장 + 오탐 유발 30장(구름, 굴뚝연기). 오탐 사진은 "연기 아님"이라고 말하는지 보려고 넣었다.

| 클래스 | 장수 |
|---|---|
| 굴뚝연기 | 15 |
| 백색회색연기 | 40 |
| 구름 | 15 |
| 흑색연기 | 30 |
| 합계 | 100 |

## 위치와 오차 반경

- 71330 사진에는 실제 연기 위치가 없어서, 예진이 만든 `docs/demo_positions.csv` 36곳을 돌아가며 **가상으로** 붙였다. 사실 목록에 `virtual: true`로 표시했다.
- 위치 구간: 낮음 34장, 높음 33장, 중간 33장
- 오차 반경은 10, 30, 50, 100m를 돌아가며 붙였다 (3.5와 같은 4단계). 반경별 결과를 6.5에서 따로 볼 수 있다.
- 판정은 3.5 본 실험 기준(최다비율 규칙, 정확도 95% 임계값)을 그대로 썼다. 서연 파이프라인(5.2)과 같은 기준이다.

| 반경 | 임계값 | 확정 | 모호 | 미확정 |
|---|---|---|---|---|
| 10m | 0.00 | 25 | 0 | 0 |
| 30m | 0.57 | 19 | 2 | 4 |
| 50m | 0.72 | 10 | 7 | 8 |
| 100m | 0.80 | 3 | 13 | 9 |

## 사실 목록 (`results/eval_facts.jsonl`)

한 줄에 사진 하나. 채점기(`tools/score_descriptions.py`)가 그대로 읽는다.

| 칸 | 뜻 |
|---|---|
| image | 사진 파일 이름 |
| class | 채점기용 클래스 이름 |
| label_class | 라벨 원래 클래스 이름 |
| flame | 화염 라벨이 있는지 |
| area_ratio | 연기 라벨 면적 / 사진 전체 면적 |
| land_use | 반경 안 용도지역 비율 |
| verdict | 확정 / 모호 / 미확정 |
| error_radius_m | 오차 반경(m) |
| risk_targets | 반경 안 위험 대상 (주거지, 산림, 농경지, 시설, 건물) |
| buildings_in_radius | 반경 안 전체 건물 수 (건물 자료에 용도 정보 없음) |
| terrain_slope_deg | DEM 90m 주변 3x3칸(270m) 경사 |
| pos_id, band, lat, lon | 붙인 가상 위치 |
| virtual | 가상 위치인지 (항상 true) |

## 채점기와 이름 맞춤

- 라벨의 `백색회색연기`가 채점기 COLOR_OK의 `백색및회색연기`와 달라서 `class`는 `백색및회색연기`로 적었다.
- 채점기는 이름에 "연기"가 들어가면 연기 사진으로 보기 때문에 `굴뚝연기`는 `class`를 `굴뚝`으로 적었다.
- 원래 이름은 `label_class`에 남겼다. 채점기를 고치게 되면 `class`를 원래 이름으로 돌리면 된다.
