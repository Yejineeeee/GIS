# 전체 파이프라인 (WBS 5.2 연결, 5.4 알람과 해설 분리)

사진부터 설명이 붙은 알람까지 한 번에 돌린다. 지도 화면은 `docs/dashboard.md` (5.5).

담당: 박서연 / 상태: 연결 완료, 알람·해설 분리 완료 (판정은 임시 규칙)

## 흐름

```
사진 → 탐지 src/pipeline/detect.py (best.pt, imgsz 960, conf 0.10)
   또는 미리 만든 탐지 결과 JSON (tools/predict_seg.py, tools/replay.py)
 → 좌표 변환 src/geo/transform.py (3.3)
 → 지리 조회 src/geo/query.py (3.4)
 → 판정 src/pipeline/verdict.py (임시. 3.6이 끝나면 judge()만 교체)
 → 알람 발행 (설명 null) src/pipeline/alert.py
      └→ (따로 도는 스레드) VLM 사실 추출 src/pipeline/vlm_client.py
         → 문장 조립 src/vlm/templates.py
         → 같은 alert_id로 설명을 붙여 다시 발행
```

## 쓰는 법

```bash
# 사진부터 한 번에 (기본)
python src/pipeline/run.py --frames 사진폴더 --weights best.pt \
    --geo-dir data/geo_jagok --sim-terrain sim/terrain_jagok3d.json --vlm fake

# 미리 만든 탐지 결과 JSON으로
python src/pipeline/run.py --detections results/replay --frames 사진폴더 \
    --geo-dir data/geo_jagok --sim-terrain sim/terrain_jagok3d.json --vlm fake
```

사진 옆에 같은 이름의 JSON(시뮬레이터 프레임)이 있으면 그 카메라 값을 쓰고,
`truth`(정답 좌표)가 있으면 알람 위치가 정답에서 몇 m 떨어졌는지, 오차 반경 안인지 함께 출력한다.
없으면 `tools/predict_seg.py`의 가정값과 시연 지역 좌표를 쓴다.

| 옵션 | 내용 |
|---|---|
| `--geo-dir` | `landuse_5179.geojson`, `buildings_5179.geojson`, DEM `*.img`가 있는 폴더 |
| `--sim-terrain` | 시뮬레이터 지형 격자 JSON. 주면 DEM 대신 쓴다. 자곡동 시뮬레이터 프레임은 `sim/terrain_jagok3d.json` (실제 드론 사진에는 DEM) |
| `--vlm none` | 설명 없이 알람만 |
| `--vlm fake` | 고정된 사실로 설명을 만든다. 연결 확인용, 결과로 쓰지 않는다 |
| `--vlm qwen` | Qwen2.5-VL-3B 4bit. GPU가 있으면 GPU |
| `--fake-sec 6` | fake VLM이 걸리는 시간을 흉내 낸다 (분리 출력 시험용) |
| `--sync` | 설명을 기다렸다가 다음 프레임으로 (5.2 방식, 비교용) |
| `--interval 1.5` | 프레임 사이를 실제처럼 띄운다 |
| `--no-merge` | 같은 사건 묶기를 끈다 |

출력은 `results/pipeline/`에 쌓인다.

| 파일 | 내용 |
|---|---|
| `detections/` | (`--weights`일 때) 프레임별 탐지 결과 JSON |
| `alerts/<alert_id>.json` | 알람의 최신 상태. 대시보드(5.5)가 읽는다 |
| `alerts.jsonl` | 발행 기록. 설명 전과 후가 차례로 쌓인다 |
| `debug.jsonl` | 형식에 없는 중간 값(대표 픽셀, 가정값, 조회 지점 수, 규칙 위반) |

끝나면 `tools/check_schema.py`로 `alerts/*.json`을 자동 검사한다.

## 임시 판정 규칙

`docs/threshold.md`의 결과를 그대로 쓴다.

## 알람과 해설 분리 (5.4)

판정까지 끝나면 설명 없이 알람을 바로 낸다(`description`, `observed`, `latency_ms.vlm`,
`latency_ms.alert_to_description`이 null). VLM 설명은 따로 도는 스레드가 만들고,
끝나면 같은 `alert_id`로 다시 낸다. VLM이 오래 걸려도 다음 프레임의 탐지와 알람은 기다리지 않는다.

- `alerts/<alert_id>.json`은 늘 최신 상태다. 쓰는 중인 파일을 대시보드가 읽지 않도록 임시 파일에 쓴 뒤 한 번에 바꾼다
- `alerts.jsonl`에는 설명 전과 후가 차례로 쌓여, 알람이 언제 나가고 설명이 언제 붙었는지 남는다
- 헛탐지 여부는 검증기 결과(`verifier`)로 알람에 남기고, 위험도가 "확인 필요"가 된다. 알람은 내리지 않는다 (11/19 회의)

### 회의 결론 반영 (11/19, 알람 v0.4)

- **설명 입력은 탐지 조각.** `observe` 가 사진 전체 대신 알람의 탐지 상자를 잘라(여백 없음, 최소 96px) 긴 변
  360px 로 줄여 넣는다(`--vlm-crop-px`, 기본 360, 0 이면 전체). CPU 4코어 기준 전체 48초 → 조각 360 중앙값
  약 9초, 연기 인식은 유지된다(`docs/inputs_cpu.md`)
- **`verifier`.** 알람을 conf 1등으로 먼저 내고(이때 null = 검증 중), 검증기가 끝나면 결과를 채워 다시 낸다.
  1등이 미통과이고 다른 탐지가 통과하면 그 탐지로 위치를 고친다(4.7 그대로). 알람이 갱신되면 새 탐지를 다시 검증한다
- **`risk`.** 알람을 낼 때마다(`Publisher.send`) `src/vlm/risk.py` 로 계산한다. 검증기 미통과면 맨 먼저 확인 필요
- **`evidence.nearest_building_m`.** 지리 조회(`src/geo/query.py`)가 원 중심에서 가장 가까운 건물까지 잰다
- 설명을 만드는 동안 검증기가 끝나면 그 결과를 문장("영상 검증 통과")과 알람에 반영한다
- 검사: 탐지 결과는 v0.3 그대로, 알람만 v0.4 (`tools/check_schema.py`)

가짜 자료 8프레임, 프레임 간격 1초, fake VLM 2초로 비교한 결과

| | 마지막 알람까지 | 알람 → 설명 (중앙값) |
|---|---|---|
| 차례대로 (`--sync`) | 23.2초 | 2.0초 |
| 분리 (기본) | 8.9초 | 4.6초 |

알람은 VLM을 기다리지 않게 되었다. 대신 VLM이 알람이 생기는 속도보다 느리면 설명이 줄을 서서
알람 → 설명 시간이 늘어난다. 실제 VLM(GGUF 35초)에서는 오래된 알람 설명을 건너뛸지 정해야 한다.

## 시뮬레이터와 실시간 연결 (5.6, 11/19)

`--watch` 를 주면 `--frames` 폴더를 지켜보다가 시뮬레이터(`tools/sim_server.py`)가 새 장을 저장하는 즉시
탐지부터 알람까지 처리한다. 알람 폴더를 `sim_server.py` 세 번째 인자로 주면 드론(`vwPursue`)이 `/latest` 로
최신 추정 위치를 읽어 따라간다. 명령은 `docs/simulator.md` "실시간 연결".

- 사진(`sim_NNNN.png`) 옆 JSON 이 끝까지 읽힐 때(다 써졌을 때) 그 장을 처리한다. 번호 순서, 쌓인 장도 건너뛰지 않는다
- 켤 때 이미 있던 장은 건너뛴다(`--watch-all` 이면 처음부터). 폴더가 없으면 만든다
- 끝내기: Ctrl+C, 폴더에 `STOP` 파일, 또는 첫 장 뒤 `--idle-sec` 동안 새 장이 없을 때. 남은 검증과 설명을 마치고 요약과 형식 검사를 낸다
- 요약에 "사진 생김 → 탐지 끝", "사진 생김 → 그 장의 알람까지" 지연(중앙값, 최대)을 낸다

확인 (11/19): 브라우저 대신 시험 프로그램이 `sim/frames_scenario` 38장을 1.5초 간격으로 `sim_server.py` 에 POST 하고
장마다 `/latest` 를 읽었다. 파이프라인(`--watch`, fake VLM 2초, 검증기 켬)과 대시보드를 같이 켰다.

- 알람 1개가 실시간으로 6번 갱신되어 미확정 276.8m → 확정 31.1m (정답과 12.9m). 형식 검사 통과
- `/latest` 가 장마다 같은 갱신을 돌려줬다(드론이 따라갈 위치). 대시보드도 1초마다 같이 바뀌었다
- 사진 생김 → 탐지 끝 중앙값 347ms(최대 449ms), → 그 장의 알람까지 355ms(최대 476ms). CPU 2코어 클라우드
- 브라우저 시뮬레이터(V-World 3D) 자체는 이 환경에서 띄우지 못했다

실제 시뮬레이터 (11/19, 박서연 노트북 WSL2): `sim_server.py` + `run.py --watch` (fake VLM) + 대시보드(8820)를 켜고
브라우저 `vworld3d.html` 에서 `vwPrepare` → `vwPursue` 를 불렀다. 드론이 보낸 장을 파이프라인이 바로 처리했고
(탐지 160~190ms, 탐지 → 알람 170~180ms), 대시보드와 `/latest` 가 갱신되어 드론이 알람 위치로 방향을 틀었다. **연결은 된다.**

- 다만 알람 4개(모두 확정)가 놓은 연기에서 약 470~540m 떨어진 도로·주거지에 났다. 탐지 신뢰도 0.11 짜리가
  도로 위 차량에 걸린 것이 보였다. 헛탐지다. fake VLM 은 검증기를 무조건 통과시키므로 걸러지지 않았다
- 시연 전에 확인할 것: 탐지 신뢰도 하한, 놓은 연기가 드론 화면에 잡혔는지, 실제 VLM 검증기로 이 헛탐지가 걸러지는지

## 같은 사건 묶기

새 탐지의 위치가 이미 낸 알람의 오차 원과 겹치면 같은 사건으로 보고 알람을 새로 내지 않는다.

### 알람 갱신 (11/15)

같은 사건의 새 탐지가 오차 반경을 지금 알람의 **80% 이하**로 줄이면, 같은 `alert_id` 로 위치, 반경,
용도 비율, 판정, 근거를 고쳐 다시 내고 설명도 새로 만든다(`--no-update` 로 끈다).

- 드론이 다가갈수록 반경이 줄어 미확정 → 확정으로 바뀌는 장면이 그대로 알람에 나온다.
  예전에는 첫 알람(수색 중, 반경 수백 m)이 끝까지 남고 뒤의 정확한 추정은 묶여서 버려졌다
- 반경이 줄 때만 고치므로 판정이 앞뒤로 흔들리지 않는다 (`tools/live_estimate.py` 의 "2장 연속" 대신)
- 같은 사건으로 묶는 원은 처음 알람 것을 그대로 쓴다. 반경이 줄었다고 같은 연기의 다른 조각이
  새 알람으로 떨어져 나가지 않게 한다
- 갱신하면 설명을 비우고(`description: null`) 새로 만든다. 만드는 동안 또 갱신되면 옛 설명은 내지 않는다
  (`alert.py` 의 `Describer._stale`)
- `alerts.jsonl` 에 갱신마다 한 줄씩 쌓이고, 대시보드가 이걸로 갱신 기록을 보여 준다. 알람 형식(v0.3)은 그대로
- `debug.jsonl` 에 `stage: "알람 갱신"` 으로 앞뒤 반경과 정답 거리를 남긴다

알람 해제는 향후 과제다.

## 남은 것

- 연기를 켠 시뮬레이터 프레임으로 다시 돌려 좌표 오차 재기
- `--vlm qwen` 실제 실행 확인 (GPU 기기)
- 설명 줄이 길어질 때 오래된 알람을 건너뛸지 (실제 VLM 속도로 시험)
- `evidence.buildings_in_radius`는 주거 건물이 아니라 전체 건물 수다 (건물 자료에 용도 정보 없음)
- 지리 조회 1초대: 건물 목록을 위치별 칸으로 미리 나눠 두면 줄일 수 있다 (query.py, 3.4 담당과 상의)
- VLM이 연기 없음이라고 답해도 알람은 남는다. 헛탐지를 알람에서 내릴지 표시만 할지 정해야 한다
