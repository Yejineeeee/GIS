# 분할 모델 학습 환경

7주차와 8주차에 잡혀 있는 학습을 시험 기간에 시작하게 되므로, 실제 데이터가 오기
전에 학습이 끝까지 도달하는지 먼저 확인했다. 성능을 본 것이 아니라 경로를 본 것이다.

담당: 이예진 / 상태: 점검 완료, 실제 데이터 대기

## 확인한 것

가짜 데이터 40장으로 학습부터 추론까지 한 번 돌렸다. 가짜 데이터는
`tools/make_fake_dataset.py`가 만든다. 연기 기둥을 그린 그림과 실제와 같은 형식의
YOLO 분할 라벨이 나온다.

| 단계 | 결과 |
|---|---|
| 학습 | 40장 40에폭에 7.4분, 최대 VRAM 2.45GB |
| 검증 | 박스 mAP50 0.665, 분할 mAP50 0.665 |
| 추론 | 첫 장 14초에서 17초, 이후 중앙값 68ms |
| 출력 | `schema/detection.example.json` 과 같은 형식으로 나옴 |

성능 숫자는 의미가 없다. 가짜 그림이고 40장이다. 신뢰도도 0.04를 넘지 않는다.
확인한 것은 데이터 로딩, 폴리곤 파싱, 가중치 저장, 검증, 추론, JSON 출력이 모두
이어진다는 것뿐이다.

## 배치 크기

| 배치 | 최대 VRAM | 40에폭 기준 |
|---|---|---|
| 4 | 0.73GB | 빠름 |
| 16 | 2.38GB | 빠름 |
| 32 | 4.34GB | 오히려 느려짐 |

여유 VRAM이 3.23GB인데 배치 32에서 4.34GB를 썼고 메모리 부족 오류가 나지 않았다.
Windows가 모자란 만큼 시스템 메모리로 넘겼기 때문이다. 오류 대신 속도로 나타난다.
같은 조건에서 배치 16이 0.3분, 배치 32가 0.5분이었다.

**실질 상한은 배치 16이다.** 오류가 안 난다고 더 키우면 안 된다.

## Windows에서 걸린 것

### main 가드

`if __name__ == "__main__":` 가드가 없으면 데이터 로더가 프로세스를 새로 띄울 때
스크립트를 처음부터 다시 실행한다. 학습이 겹쳐서 돌다가 멈춘다. 학습은 끝났는데
마지막 검증에서 터지는 형태로 나타나서 원인을 찾기 어렵다.

`tools/train_seg.py`와 `tools/predict_seg.py`의 가드를 지우지 말 것.

### 저장 위치

ultralytics에는 전역 설정 `runs_dir`이 있다. 기본값이
`C:\Users\<사용자>\runs`여서, `project="runs"`처럼 상대 경로를 주면 저장소가 아니라
그쪽에 저장된다. 학습은 성공했는데 가중치가 안 보이는 상황이 된다.

절대 경로로 넘기고, 저장 위치는 짐작하지 말고 `model.trainer.save_dir`에서 읽는다.

### 추론 첫 장

첫 장이 14초에서 17초 걸리고 두 번째부터 68ms로 떨어진다. 실제 운영에서는 드론이
뜨기 전에 빈 이미지로 한 번 돌려 모델을 데워야 한다. 현장 기기 동작 시간을 잴 때
첫 장을 넣으면 숫자가 크게 틀어진다.

## 실제 학습 시간 예상

가짜 데이터 기준으로 장당 에폭당 0.0046분이었다. 300장에 100에폭이면 약 2시간
20분이다. 실제 이미지는 해상도가 크므로 더 걸린다. 노트북에서 돌려도 되는 규모이나,
여러 번 돌려 볼 것이므로 Colab을 같이 쓴다.

## 쓰는 법

```
python tools/make_fake_dataset.py data/fake 40          가짜 데이터
python tools/convert_labels.py --inspect "라벨 폴더"     실제 라벨 구조 확인
python tools/convert_labels.py "라벨 폴더" data/yolo     실제 라벨 변환
python tools/train_seg.py data/yolo/dataset.yaml 100 640 16
python tools/predict_seg.py runs/smoke/weights/best.pt data/pilot
```

`DET_CONF`로 탐지 임계값을, `SEG_MODEL`로 사전학습 가중치를 바꾼다.

## 라이선스

ultralytics는 AGPL-3.0이다. 수업 과제와 연구 목적에는 문제가 없으나 상업적으로
쓰려면 별도 허락이 필요하다. Qwen2.5-VL-3B와 같은 상황이다.
