# 71330 드론 사진 선별 목록 (WBS 2.2)

분할 모델 학습(2.4)에 쓸 300장을 고른 기준과 결과를 정리한다.

담당: 이수진 / 상태: 검토 요청

- 목록: `docs/select_71330.csv` (file_name, class, place 외에 split, db, 연기 여부, 영상 번호, 이미지 파일 이름, GPS 포함)
- 선별 코드: `python3 tools/select_71330.py <drone_env.csv>`
- 입력 `drone_env.csv`: Validation 라벨(VL.zip, 69,635개) 중 드론 촬영분 14,067개의 파일 이름, 영상 번호, 장소, GPS, 고도 목록

## 선별 기준

| 기준 | 내용 | 이유 |
|---|---|---|
| 촬영 장비 | 드론만 | 과제 대상이 드론 영상 |
| 연기 사진 | PositiveRealDB의 흑색연기 135, 백색회색연기 135 | 데이터셋이 실제 촬영분으로 분류한 사진. 발화원은 아래 표 참고 (연막탄 포함) |
| 오탐 유발 사진 | NegativeDB의 구름, 안개연무, 굴뚝연기 각 10장 (전체의 10%) | 연기가 없는 사진도 넣어 오탐을 줄임 |
| 화염 | 제외 | 학습은 연기 1클래스 |
| 영상당 장수 | 영상(camera_id + video_id)당 1장. 뽑은 영상 집합을 전체에서 하나로 관리 | 같은 영상의 비슷한 프레임이 겹치지 않게. 클래스가 달라도 같은 영상은 한 번만 |
| 제외 지역 | 모래고개입구, 장현동 | 시연과 평가 후보 지역이라 학습에서 뺌 |
| 학습/검증 나누기 | 영상 단위로 train 80%, val 20% | 같은 영상이 양쪽에 섞이지 않게 |
| 재현성 | 난수 시드 42 고정 | 다시 돌려도 같은 목록 |

## 발화원 (PositiveRealDB에도 연막탄이 들어 있음)

`PositiveRealDB`는 "모의 발화를 뺀 실제 발화"라는 뜻이 아니다. 파일 이름의 발화원 칸을 세면 PositiveRealDB 안에도 연막탄 사진이 많다. 예: `PositiveRealDB_흑색연기_강원도강릉시시루봉정상입구_RD020033_001_연막탄(흑색)_00002279.jpg`

따라서 이 목록은 연막탄 등 모의 발화를 제외한 목록이 아니다.

| 발화원 | 연기 사진 270장 중 |
|---|---|
| 연막탄(흑색) | 146 |
| 액체연료 | 47 |
| 연막탄(백색) | 34 |
| 나뭇잎 | 33 |
| 나머지 (나무장작 4, 목탄 2, 연기발생기 1, 종이 1, 번개탄 1, 기타 1) | 10 |

- 연막탄(흑색·백색)과 연기발생기가 181장(67%)이다

## 처음 요청과 다른 점

처음 요청은 "장현동과 솔향수목원 위주"였지만 아래 이유로 장소를 골고루 뽑았다. 10/8 회의 리뷰(PR 4)에서 이 목록을 바꾸지 않고 문서만 고치기로 했다.

- 장현동: 연기 사진이 PositiveSyntheticDB 백색회색연기 128장뿐이고 PositiveRealDB 연기 사진은 0장이다. 또 시연 후보 지역이라 학습에서 빼야 평가와 섞이지 않는다
- 모래고개입구: 10/8 회의에서 시연 지역으로 제안됐다. 시연 사진이 학습에 섞이지 않게 학습에서 뺐다
- 솔향수목원: 115장(38%)으로 가장 많이 들어갔다. 장소별로 돌아가며 뽑아 한 장소에 몰리지 않게 했다

## 원천 데이터(사진) 받는 단위

- 장 단위로 받을 수 없다. Validation 원천 데이터는 `VS.zip` 1개(74GB)로만 제공된다
- Training 원천 데이터(`TS`)는 수백 GB 분할 압축이라 쓰지 않는다
- 방법: `VS.zip`을 받은 뒤, 압축을 전부 풀지 않고 목록의 300장(`image_file`)만 꺼낸다
- 필요한 저장 공간: 약 74GB + 여유분

## 확인된 문제: 공통 GPS 값

- 드론 사진 14,067장의 GPS 값은 20종류뿐이다
- 그중 `37.697849, 128.861917`(elevation 93)이 6,977장(49.6%)에 들어 있고, 강릉뿐 아니라 경기도 광명시·안산시, 서울 금천구, 인천 계양구, 강원도 삼척시·평창군 등 서로 다른 장소 18곳에 같은 값이 쓰였다
- 따라서 이 값은 실제 촬영 위치가 아니라 기본값으로 채운 것으로 보고, 위치 계산에서 제외한다
- 솔향수목원 3,001장은 전부 이 공통 값이라 위치 정보가 없다
- 이전 문서(`data_71330.md`, `gsd.md`)에서 "GPS 100% 채워짐", "샘플 GPS는 구정면"이라고 적은 부분은 이 공통 값을 본 것이다

## 확인된 문제: elevation의 의미 (정정)

- 공통 값이 아닌 GPS 19곳에서 elevation과 DEM 지면 높이를 비교하면, 차이가 -7m ~ +31m로 지면 높이와 비슷하다 (예: 114 vs 115m, 0 vs 0.2m, 144 vs 146m)
- elevation은 드론의 비행 높이(지면 기준)가 아니라, 촬영 지점의 해발 고도에 가까운 값으로 보인다
- `gsd.md`에서 "elevation은 지면으로부터의 높이"라고 결론 낸 것은 공통 GPS 값(지면 147m, elevation 93)으로 비교한 결과라 정정한다
- 영향: 지면 기준 비행 높이를 데이터에서 알 수 없으므로, GSD와 오차 반경 계산(3.3)에는 비행 높이를 가정값으로 넣어야 한다
