# VLM 이 있을 때와 없을 때 (WBS 4.7)

"YOLO 와 템플릿만으로도 같은 문장이 나오지 않느냐"에 답하려고, VLM 이 맡는 일을
셋으로 나눠 VLM 없이 하는 방식과 같은 사진으로 비교했다.

담당: 이예진 / 상태: 비교 완료, 검증기를 파이프라인에 넣음. 연기색은 탐지 조각으로 다시 잼

```
python tools/compare_vlm.py
```

모델은 다시 돌리지 않았다. 아래 저장 결과를 읽는다.

- 후보 검증기, 실제 사진 100장: `runs/verify_real/verify_real.jsonl` (`docs/vlm_base_pick.md`)
- 후보 검증기, 시뮬레이터 31장: `runs/verify/verify.jsonl`
- 사진 전체를 본 VLM 답, 평가셋 100장: `results/eval_method_iii.jsonl` (`docs/generation_methods.md`)
- 정답: `results/eval_facts.jsonl` (71330 라벨)

## 결과

| VLM 이 맡는 일 | VLM 없음 | VLM 있음 | 판단 |
|---|---|---|---|
| 좌표에 쓸 탐지 고르기 (실제 63장) | 헛탐지로 좌표를 낸 사진 7장 | 3장 (고침 4, 망침 0) | 도움이 된다 |
| 좌표 오차 (시뮬레이터 31장) | 평균 69.7m, 100m 초과 6장 | 59.1m, 5장 (좋아짐 4, 나빠짐 1) | 도움이 된다 |
| 알람, 사진 전체를 본 VLM (100장) | YOLO 88/100 | 62/100 | YOLO 보다 나쁘다 |
| 알람, 검증기 통과 탐지 (100장) | YOLO 88/100 | 85/100 | 헛경보는 줄지만 놓침이 는다 |
| 연기색 (연기 사진 70장) | 늘 "흰색/회색"이라고 쓰면 40/70 | 21/70 | 늘 같은 답보다 나쁘다 |
| 불꽃 | | | 평가셋에 불꽃 사진이 없어 잴 수 없다 |

**VLM 이 YOLO 보다 나은 일은 탐지 조각을 잘라 보여 주고 연기인지 묻는 것 하나다.**
사진 전체를 보여 주고 묻는 연기 유무와 연기색은 VLM 을 쓰지 않는 쪽이 낫다.

## 1. 좌표에 쓸 탐지 고르기

VLM 없음은 YOLO conf 1등, VLM 있음은 검증기 P(예) 0.7 이상 중 conf 1등이다. 통과한
것이 없으면 conf 1등을 쓴다.

- 실제 사진: 탐지가 있는 연기 사진 63장 중 좌표에 쓴 탐지가 헛탐지(밭, 맨땅 등)인
  사진이 7장에서 3장으로 줄었다. 바뀐 4장은 모두 좋아졌고 나빠진 사진은 없다
- 시뮬레이터: 5장이 바뀌었다. 400m 비닐하우스 사진이 276.0m 에서 21.8m 로, 200m,
  300m 두 장이 70~90m 에서 40m 안으로 줄었다. 240도 200m 한 장은 16.0m 에서 27.0m 로
  나빠졌다
- 둘 다 방향은 같지만 바뀐 사진이 적어 우연이라고 배제할 수 없다(실제 사진 McNemar
  정확 검정 p=0.125). 바뀌지 않은 사진이 많은 것은 대부분 conf 1등이 이미 연기라서다

## 2. 알람

| 방식 | 맞춤 | 연기 사진 잡음 | 오탐 사진 알람 |
|---|---|---|---|
| 항상 "있다" (기준선) | 70/100 | 70/70 | 30/30 |
| VLM 없음: YOLO 탐지가 있으면 | **88/100** | 63/70 | 5/30 |
| 검증기를 통과한 탐지가 있으면 | 85/100 | 58/70 | 3/30 |
| 사진 전체를 본 VLM 답 | 62/100 | 45/70 | 13/30 |

- 사진 전체를 본 VLM 은 YOLO 보다 확실히 나쁘다(YOLO 만 맞은 사진 28, VLM 만 맞은
  사진 2, p<0.001). 같은 모델이 탐지 조각을 잘라 보여 주면 AUC 0.90 이므로, 사진 전체에서
  연기가 작게 보이는 것이 원인으로 보인다
- 검증기를 알람에도 걸면 헛경보가 5장에서 3장으로 줄지만 연기 사진 5장을 더 놓친다.
  남은 헛경보 3장은 굴뚝연기라 이 질문으로는 걸러지지 않는다. 그래서 알람은 YOLO
  기준 그대로 둔다(`docs/vlm_base_pick.md`)
- 여기서 "연기 사진 잡음"은 탐지가 하나라도 있는 사진이다. 연기와 겹친 탐지만 세면
  YOLO 는 60/70 이다

## 3. 설명에 들어가는 사실

- 연기색: 정답은 흰색/회색 40장, 검은색 30장인데 VLM 은 검은색 41장, 없음 29장으로
  답했고 흰색이나 회색은 한 번도 답하지 않았다. 늘 "흰색/회색"이라고 쓰는 것(40/70)
  보다 못한 21/70 이다. (4.6 의 38% 는 오탐 사진 30장의 "없음"까지 넣어 100장으로 센 값이다)
- 불꽃: 평가셋 100장 모두 불꽃이 없고 VLM 도 모두 없다고 답했다. 맞힌 것이 아니라
  잴 수 없는 것이다

### 연기색을 탐지 조각으로 다시 재기

`tools/smoke_color.py`. 연기 사진의 탐지 중 연기 라벨과 겹치는 126개(검은색 62, 밝은색
64)를 후보 검증기와 같은 방식으로 잘라 색을 물었다. VLM 없이 마스크 안 밝기만으로
가르는 방식도 같은 탐지로 쟀다. 정답은 겹치는 연기 라벨의 분류(흑색연기, 백색/회색연기)다.
문턱은 사진 번호 홀짝으로 나눠 한쪽에서 정하고 다른 쪽에 썼다.

사진 단위(좌표에 쓰는 탐지가 연기인 60장, 검은색 27, 밝은색 33)

| 방식 | 맞춤 | 검은색 | 밝은색 | AUC |
|---|---|---|---|---|
| 늘 "밝은색" | 33/60 | 0/27 | 33/33 | |
| 사진 전체로 묻기 (4.6) | 21/70 | | | |
| 조각, 한국어로 묻기 | 42/60 | 22/27 | 20/33 | 0.78 |
| 조각, 영어로 묻기 | 41/60 | 16/27 | 25/33 | 0.76 |
| 마스크 안 밝기 | 34/60 | 10/27 | 24/33 | 0.64 |
| 주변과 밝기 차 | 31/60 | 9/27 | 22/33 | 0.54 |

- 잘라 보여 주면 확실히 나아진다. 사진 전체로는 늘 같은 답보다 못했는데, 조각으로는
  AUC 0.76~0.78 이다
- 한국어로 물으면 "검"으로 크게 쏠린다. 확률 0.5 로 가르면 126개 모두 검은색이라고
  답했고, 문턱을 0.08 근처로 내려야 맞는다. ① 후보 지점 선택에서 본 글자 순서 쏠림과
  같은 결이다. 영어는 쏠림이 작다
- 밝기만으로는 가르지 못한다. 흰 연기도 옅으면 아래 땅 색이 비치고, 검은 연기도 햇빛을
  받으면 밝게 찍힌다
- 그래도 사진 열 장 중 셋은 색을 틀린다. 문장에 "검은색 연기"라고 단정하기에는 부족하다

탐지 단위 126개로도 같은 결과다(한국어 교차 문턱 81/126, 영어 72/126, 늘 "밝은색" 64/126).

## 정리와 바꿀 것

VLM 의 역할을 "탐지 조각이 연기인지 판정"으로 좁힌다.

- 후보 검증기를 `src/pipeline/run.py` 에 넣는다. 좌표에 쓸 탐지만 고르고 알람은 YOLO
  기준 그대로다 (11주차 반영, 아래)
- 사진 전체를 보고 연기 유무를 묻지 않는다. 연기 유무는 YOLO 로 정한다
- 연기색은 문장에서 뺀다. 탐지 조각으로 물으면 70% 까지 오르지만 열 장 중 셋을 틀린다.
  색이 꼭 필요하면 "추정"으로 표시하고, 영어로 묻는다
- 불꽃은 불꽃이 든 사진을 평가셋에 넣기 전까지 결과를 주장하지 않는다

## 파이프라인에 넣은 결과

위 결과대로 바꿨다.

- `src/pipeline/run.py`: 알람은 YOLO conf 1등 탐지로 먼저 낸다. 그 뒤 따로 도는 스레드에서
  후보 검증기를 돌려, P(예) 0.7 이상인 탐지 중 conf 1등이 처음 것과 다르면 같은 alert_id 로
  위치와 판정을 고쳐 다시 낸다. 다른 자리에서 통과한 탐지는 새 알람이 된다. 이미 낸 알람과
  같은 사건으로 묶일 탐지는 묻지 않는다. `--no-verify` 로 끈다
- `src/pipeline/alert.py`: 설명은 검증이 남아 있으면 기다린다. 같은 GPU 에서 위치를 고치는
  일을 먼저 한다
- `src/pipeline/vlm_client.py`: `p_smoke()` 를 더했다. 설명과 같은 모델을 쓰므로 VRAM 이
  늘지 않는다. 두 스레드가 번갈아 쓰도록 잠금을 넣었다. GPU 계산 dtype 을 fp16 에서
  bf16 으로 바꿨다(fp16 NaN 문제)
- `src/vlm/templates.py`: 문장에서 연기 유무, 색, 퍼짐을 뺐다. "연기가 탐지되었다"로
  시작한다. 4.6 실험 재현은 `build(..., use_vlm_facts=True)`

시뮬레이터 프레임 32장(탐지 117개)을 프레임 간격 1.5초로 돌렸다(RTX 3050 4GB). 지형은
V-World DEM 이라 시뮬레이터 지형과 달라 오차가 크게 나온다(`docs/simulator.md` 11/04).
그래서 실행끼리의 상대 비교만 본다.

| | 검증기 끔 | 알람 전에 검증 | 알람 먼저 | **알람 먼저, 묶이면 생략, 검증 먼저** |
|---|---|---|---|---|
| 알람 | 47 | 29 | 28 | **28** |
| 정답에서 100m 넘게 떨어진 알람 | 27 | 14 | 13 | **13** |
| 검증기 호출 | | 117 | 117 | **74** |
| 탐지에서 알람까지 중앙값 | 2.0초 | 15.2초 | 2.8초 | **1.9초** |
| 탐지에서 알람까지 최대 | 9.7초 | 38.4초 | 736.9초 | **21.7초** |
| 알람 뒤 위치 수정까지 | | | 102.0초 | **11.7, 15.5초** |
| 알람 뒤 설명까지 중앙값 | | 17.5초 | 199.5초 | 148.5초 |
| 전체 걸린 시간 | 68초 | 921초 | 855초 | **286초** |

(검증기 끔은 `--vlm none`, 알람 전에 검증은 `--sync` 로 돌려 설명 시간도 들어 있다)

- 헛탐지 자리로 가는 알람이 절반으로 줄었다(27 → 13). 비닐하우스처럼 수백 m 떨어진
  헛탐지 알람이 빠졌다
- 알람 전에 검증하면 검증기 한 번에 약 2.8초가 걸려 알람이 15초 늦어진다. 알람을
  먼저 내도록 바꾸자 알람 지연은 검증기가 없을 때와 같아졌다
- 그런데 GPU 하나로 검증과 설명을 다 하자 대기열이 밀려, 늦게 뜬 알람은 12분 뒤에 나왔다.
  같은 사건으로 묶일 탐지(큰 연기를 쪼갠 조각)를 묻지 않자 호출이 117 → 74 로 줄고,
  검증을 설명보다 먼저 하자 위치 수정이 12~16초 안에 왔다
- 대신 설명이 밀린다(알람 뒤 중앙값 149초). 설명은 사람이 읽는 것이라 위치보다 늦어도
  된다고 보았다. 현장 기기(CPU)에서는 검증기와 설명이 모두 더 느리므로 7.3 에서 다시 잰다

설명 문장 예

```
[확정]   연기가 탐지되었다. 자연녹지지역에서 발생했다. 좌표 오차 반경은 15.5미터다. 주변이 산림이다. 반경 안 건물은 2개다.
[미확정] 연기가 탐지되었다. 좌표 오차 반경이 26.3미터여서 정확한 용도는 알 수 없다. 주변이 농경지다. 반경 안 건물은 5개다.
```

## 한계

- 바뀐 사진이 실제 4장, 시뮬레이터 5장으로 적다. 방향은 일관되지만 통계적으로
  확정할 수준은 아니다
- 실제 사진에는 정답 좌표가 없어 "헛탐지로 좌표를 낸 사진 수"로 쟀다. 미터 단위
  개선은 시뮬레이터에서만 쟀다
- 검증기 문턱 0.7 은 시뮬레이터에서 정한 값이고 실제 사진에서도 그대로 썼다
- 탐지의 연기 여부는 박스 기준(IoU 0.1 이상 또는 중심이 안)이다. `docs/detect_eval.md`
  는 마스크 기준이라 놓친 연기 사진이 10장 대 9장으로 하나 다르다
